# 12 · Codex 工作指令

以下指令在实际代码仓库中使用。第一天未建代码仓库时先用包内 README 的完整开工指令。不要一次把所有文档全文塞进一条提示词；按任务读取所需文件。

## 接续开发

```text
继续这个录音机项目。先读 AGENTS.md 和 docs/13-HANDOFF.md，检查 git status、
当前提交和适用规则，确认文档记录与实际代码一致。按 docs/07-BACKLOG.md
执行下一个未完成任务，完成实现及针对性验证，不要重做已通过的选型。
遇到新用户要求时同步 01 和相关 ADR。结束前更新 13，给出下一条可执行任务。
```

## 实现一项功能

```text
本次完成任务 T20：WAV 录音起止与可靠写盘。
先读 01、02、03、04、06、08 的相关部分，检查已有 capture/analysis 接口。
实现录音写盘分支和引擎确认的采样帧边界，保持 LIVE 采集不中断，take 累计独立。
覆盖正常停止、重复 stop、静音段、写盘失败，按 A04/A06 验证。
不要把 renderer 的波形缓存当 PCM 源。交付代码、运行证据和更新后的接力记录。
```

其他任务替换 T 编号、相关 A 编号与目标，不只说“把下一步做完”。

## 排查构建失败

```text
先复现并保留第一个真实错误，记录工作目录、构建目标、工具版本和退出码。
区分依赖下载、Node/Electron ABI、MSVC/SDK、原生代码、打包资源的问题。
对照锁文件与实际脚本，做最小修复并重跑对应门槛。
不要通过升级所有依赖、禁用安全设置、删除整套测试或改成模拟设备来绕过错误。
```

## 排查声音/表头错位

```text
按 03 和 06 追踪一个确定文件的解码帧、输出已呈现位置、游标、levelIndexFrame
和 loudnessIndexFrame。
记录 assetId、sampleRate、generation、缓冲/编码延迟及实际查询索引。
使用带头尾脉冲的已知素材验证，区分音频延迟、缓存量化和旧 seek 结果覆盖。
修复根因并复跑 A10，不通过给游标写固定偏移量掩盖所有设备的差异。
```

## 阶段复核

```text
对照本阶段关联的 R 和 A 编号复核实现。先读实际代码与已有证据，优先查
丢帧、错误时间基准、源/成品缓存混用、累积语义、状态竞争和恢复风险。
只补充能覆盖具体风险的必要检查，区分阻断问题与次要视觉问题。
给出发现、证据、修复和剩余限制；不得把未执行项写成通过。
```

## 会话交接

```text
把当前状态写入 docs/13-HANDOFF.md：已完成任务、代码根、提交/未提交变更、
精确运行命令与结果、未验证项、当前阻塞、下一个任务及其首条命令。
保证新会话只读 AGENTS.md、13 和相关任务文档就能继续，不依赖口头“刚才做过”。
```

`AGENTS.md` 保持简短，详细产品和架构不堆入同一文件。把项目约定放到实际仓库根，切换到代码仓库后检查 Codex 读到的规则，避免仍只打开外层文档目录。依据见 14 的官方 Codex 项目指令文档。
