## 证据范围

云端 Linux 可以验证 TypeScript 服务、真实进程故障、可移植 C++ DSP、原始 EBU 材料、浏览器模拟数据与资源上限。Windows 云端 CI 可以验证原生编译、Job Object 和故障注入；真实 WASAPI、安装包人工使用、实体设备、断电恢复与听感仍须实体环境验收，不能用云端信号代替。

## 迭代日志

- R83-01：分析服务固定 2048 次耗时窗口、采集包与写盘/检查点固定 32 桶计时器。计时不包含音频、路径或设备身份；原生分位数为 log2 微秒桶上界，计数为引擎对象生命周期累计。云端 `spectral_benchmark` 在 30/600/7200 秒位置运行确定性合成 PCM 的实际生产 DSP；每次只驻留一个短窗口，不是长文件 I/O、完整概览或 WASAPI 性能证明。
- R83-02：主进程在允许监督进程启动编码器前，将监督进程纳入 Windows `KILL_ON_JOB_CLOSE` Job Object；所有后代继承。Linux 创建独立进程组，监督进程 exit 即清理整组（早于 close，避免后代持管道导致悬挂）。普通取消、IPC 断开、监督进程强杀和拥有进程硬退出分别验证。Windows 正常清理用异步 worker 确认 Job 的 ActiveProcesses 归零后才返回结果，不阻塞主线程。

源码 preview.32；当前状态与源码/分发身份同步到 13。

## 功能与协议

- R83-03：每个分析线程最多复用两份 FFT/Hann/输入与复数工作区；只复用计算配置，不保留 PCM 或历史累计。声谱列跳过声场计算。既有 double DFT、位置与查询顺序验收保持不变。18 组同机内核对照中位加速约 2.15 倍，逐项结果见 research/2026-10-11-spectral-kernel-benchmark.json。
- R83-04：文件声谱使用时间/频率峰值金字塔，随视口宽度选择级别。混合缺口掩码和有效比例保留；概览跨边界可能包含相邻分组峰值，明确显示级别与分组尺寸，精确悬停仍读取原始 FFT。内存概览预算 8 MiB，计入原声谱总预算；磁盘每素材 96 MiB、所有登记素材 256 MiB，先淘汰原始 tile 与低层概览，再淘汰高层。登记索引和 cache owner 标记持久化；索引损坏会隔离并在素材访问时重建，诊断暴露 registryRecovered，不能宣称未重新发现的离线旧缓存也已计入。原始音频、恢复音频、未知文件、链接和正在读写的缓存不参与淘汰。
- R83-05：InstrumentSettings v2 增加 smoothing=0/3/6/12/24 与 tilt=±6 dB/oct；v1 严格迁移为关闭/0。平滑在原始线性功率上按部分频点权重平均，显示按像素取峰值；倾斜以 1 kHz 为基准。显示配置不进入分析缓存键，不改变 LUFS、原始频点或 dBFS 单位。
- R83-06：范围 I 与 TP 就绪且计量身份一致后可开启等响度回听，目标=min(IA,IB,IA−1−TPA,IB−1−TPB)，只衰减，保留至少 −1 dBTP 的测量余量。手动音量与匹配系数独立，范围变更关闭匹配；计量不可用时返回明确状态。来源完整性不足时即使 I/TP 数值 ready 也拒绝匹配；已校验导入来源明确标为当前内容完整，这不证明其原始采集过程。原生播放仅在输出路径加入 5 ms 线性增益过渡，捕获、计量、导出都不应用匹配。声卡输出与切换听感待实体环境。
- R83-07：主进程核对实际 PCM 内容哈希后读写独立 marker v1 元数据，最多 512 个点/范围标记，支持评论、编辑、删除、跳转；缓存清理不删除标记。报告包含标记快照与身份核验后跳转。频谱及声谱支持独立 SVG/PNG，嵌入/附带来源哈希、轴、真实采样率、帧、Hann/FFT、平滑、倾斜和质量说明；LIVE 须先显式冻结。PNG 从主进程生成的 SVG 在实际浏览器绘制并验证尺寸后保存。图表任务与票据有界，录音/退出会取消声谱导出任务。
- R83-08：报告 distribution v1 为固定 1 LU 桶、按原始帧时长加权的 M/S 分布，分别记录有效/静音/排除帧及上下溢出；PLR=范围最大 TP−范围 I，PSR=缓存中最近 3 s 的最大 TP−同游标 S，并提供有效时间加权平均与最大。PSR 的 TP 来自 10 ms 缓存区间，非样本精确或测量认证。静音、未就绪、缺口、错误与来源质量不足不输出有效动态比值。既有 Meter v5、AnalysisCache schema 1/key 3 不变；Request v1 白名单为增量扩充，Report v1 增量字段单独标为 marker/distribution v1。

## 长文件实测

[完整 18 组结果](research/2026-10-11-long-file-benchmark.json)来自实际写出的合成 mono float32 WAV、测试端有界 PCM 读取器、生产可移植 DSP 和生产 TypeScript 声谱服务。首次生成与 24 次热视图完全一致；快速 seek、精确悬停、6 次交替来源与隐藏取消通过。交替来源测试是分析服务负载，不是声卡 A/B 回听。缓存冷启动指派生缓存为空，未清除 OS 页缓存；并行验证和 GC 会影响云端耗时，不能当作特定用户电脑的承诺。

| 2 小时来源 | FFT | 首次整段概览 s | 热视图 p95 ms | 原始悬停 p95 ms | 派生缓存 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 44.1 kHz | 2048 | 144.44 | 4.55 | 0.026 | 95.97 |
| 44.1 kHz | 16384 | 410.55 | 4.00 | 0.033 | 95.72 |
| 48 kHz | 2048 | 256.79 | 5.61 | 0.044 | 76.61 |
| 48 kHz | 16384 | 499.26 | 5.04 | 0.028 | 95.72 |
| 96 kHz | 2048 | 537.99 | 4.39 | 0.029 | 40.57 |
| 96 kHz | 16384 | 473.48 | 5.23 | 0.049 | 82.35 |

18 组缓存数组/投影/概览均符合 64 MiB 测试预算，派生磁盘最大约 95.97 MiB。整个 Node 进程峰值 RSS 约 417.00 MiB，原生探针约 5.27 MiB；64 MiB 是服务缓存预算，不是应用总 RSS。首次完整概览仍需分钟级离线工作，应保留就绪/取消状态，后续再单独评估初次生成吞吐；本轮不把内核约 2.15 倍加速外推为完整导入或实时录音速度。

第一轮长文件试验发现按时间淘汰会丢掉高层概览，导致热视图重复 FFT；已修为先淘汰原始/低层并增加内存与磁盘压力回归，以上矩阵是修复后完整重跑。JSON 的 rawAndHotIdentical 字段表示首次生成与热缓存投影一致，独立原始峰值/掩码对照由单独测试验证。

```sh
npm run typecheck
npm test
npm run build:trace
cmake -S native/portable -B build/portable -DCMAKE_BUILD_TYPE=Release -DTRACE_REQUIRE_EBU=ON

```
