# 52 · M12 外部素材与参考比较设计

2026-09-17。**导入服务与界面已接入开发构建；参考与阶段交付待完成。** M11 工程关口已通过；本文件固定可以独立推进的资产边界与工作票，不表示已交付导入或参考功能。执行范围沿用 [38](38-DEVELOPMENT-PLAN.md) M12，不加入同录同播、编辑器或云服务。

## 1. 当前复用点与缺口

已查实际源码：PlaybackService.open 接收 AnalysisSource，频谱/声场/声谱图和 M11 报告都已按来源身份与帧范围工作。ExportService 通过 RecordingService 的 session/sessions/analysisSource 获取资料；真正用到的持久化宿主主要是 directory、document.sessionId/name/exports、save/event。

RecordingService.analysisSource 现仅允许会话目录 audio/ 内的 WAV，SessionDocument 包含采集区域与时钟。这些录音归属约束继续保留；外部文件采用独立导入模型，不伪造录音设备/采集时间来填满会话字段。

mediaTasks 已有锁定 FFmpeg/ffprobe、单流检查、分段 float32 解码、取消和 decoded frame 验证。但现有 decodeMedia 面向 Trace 自己的成品，已知编码前逻辑帧和 DecodeRecipe；外部文件不能套用这个“已知原长度”假设。

## 2. 资产与目录归属

新增 ImportService 与版本化 ImportedAsset；目录使用应用 userData 下的独立 imports/UUID。文件记录包含来源路径、大小/修改时间、SHA256、实际格式、解码器身份、已验证解码帧数、准备状态与派生成品；实际类型在实现时落地。

| 内容 | 归属 | 清理/移除行为 |
| --- | --- | --- |
| 用户选定的原文件 | 外部、只读 | 不改写、不重命名、不移入回收站；移除只解除引用 |
| import.json 和应用索引 | Trace 元数据 | 身份验证后更新/移除；坏记录隔离，不吞掉其他记录 |
| decoded/analysis/spectral | Trace 可重建缓存 | 取消消费者并等待关闭后清理；不沿链接遍历到外部目录 |
| 应用内派生成品 | Trace 生成、可能是用户唯一成品 | 与缓存区分；清理缓存不删除，移除时保留或明确处理 |
| 用户“另存”的成品/报告 | 用户保存内容 | 不因库记录或缓存移除而删除 |

导入路径只由主进程文件对话框或 Electron preload 的真实 File 对象提取，renderer 不获得通用文件读写 API。内容身份使用实际 hash，大小/mtime 仅用于快速变更提示；重新打开/重建前复核。外部移动后可以重新定位，内容不同须建立新版本并使旧分析、参考和跳转失效，不能给新文件套用旧读数。

导入索引独立于录音目录，切录音保存目录不会悄悄丢失外部引用。原文件路径仅保存在本地用户数据，不写入源码、报告公开页面或遥测。

## 3. 解码与帧语义

第一批接通 WAV、MP3、AAC-M4A 和 ADTS，本期仍为单/双声道、8–96 kHz 范围；具体编码白名单在实现前固定，不能只根据后缀接受。多音轨、超过两声道、超范围采样率明确拒绝，不静默选择轨道或降混。

使用独立后台任务逐块解码成原采样率/声道的 float32 分段缓存，再复用现有原生文件分析。WAV 16/24-bit 与 float32 做逐样本/帧数对照，避免无意重采样或量化。是否直接读取已支持 WAV 在正确性证据后再优化，不为节省缓存牺牲统一语义。

MP3/M4A 使用锁定解码器读取可用 gapless 元数据；以实际解码后完整帧数作为时间轴长度，记录媒体身份和解码器版本。ADTS 没有可靠的原始编辑长度时保留实际解码内容，不猜测删除头尾样本；报告说明口径。探测 duration 只是进度估计，不能作为最终帧数。

首次导入做磁盘容量预检；所有缓存有来源/任务标记，失败与取消清理本任务创建的部分并保留原文件。导入/解码/分析采用有界队列、录音优先，与报告/编码的后台调度避免无界并发；具体限额复用已有预算并在实现入口记录。

## 4. 应用接入边界

提取 ExportService 所需的窄 ExportRepository/ExportOwner 接口，由组合仓库分派录音与导入资料。RecordingService 继续拥有录音生命周期；ImportService 拥有外部元数据/解码缓存；不将外部路径放进现有 audio/ 相对路径字段。

统一来源解析覆盖 file.open、analysis.start、export.describe/start、spectrogram/instrument 和 report.prepare。报告增加明确的来源性质：外部文件完整读取校验不代表曾经的录制过程已获证明。外部文件可按所选范围判断目标，来源说明不宣称不存在录制缺失。

文件库同屏显示“录音/外部素材”性质及准备、可用、缺失、变化、失败状态。保持搜索、排序、打开位置、取消/重试和缓存管理的一致入口；外部素材移除按钮文字应说明“移除引用”。文件拖放区域不遮挡日常时间轴手势。

## 5. 单份参考素材

ReferenceService 持有一份已保存的 B 来源及独立分析引用；主工作台来源为 A。A、B 各自保留游标、范围、分析身份和测量结果。主仪器显示的来源始终明确，参考计算不能覆盖 A 的 MeterSnapshot 或累计 I。

- 支持为 A/B 选择整段或各自范围，并明确时间偏移。以秒转换至各自采样帧，不能直接复用不同采样率的帧号。
- 频谱比较使用相同窗类型/FFT 点数、平均/保持与声道模式。频率轴按 Hz 对齐，显示两份素材的实际分辨率/窗口时长，不把两个 bin 索引直接叠加，也不暗中重采样。
- 比较读数采用各自独立范围分析的 I/TP/LRA；不足/静音/缺口保留状态，只有双方可比较时给差值。I 差值单位 LU，峰值差值单位 dB。
- A/B 试听串行切换；只有一个音频输出，先停止旧输出再启用新来源。试听增益只影响输出、不改变测量；录音中继续保持禁止回听。
- 缺失/替换/清理 B 时先取消并等待查询，明确参考不可用，不保留错误的参考曲线。切回实时后不将 B 读数当成实时输入。

## 8. 独立解码底座进展

importMedia.ts 已实现严格容器/音轨/编码判定、文件指纹、容量预检、原采样率/声道的 float32 分段解码、前后内容核验，以及带 owner.json 的精确清理。复用 mediaTasks.floatWave，未改变原编码/采集算法。当前不支持 WAV PCM32 integer、HE-AAC、多音轨、普通视频、多于两声道或超过 96 kHz；封面图片可随单一音轨被忽略。

两项格式判定测试通过，实际 FFmpeg 独立流程 6 项通过：artifacts/m12/import-1789596014436/report.json。测试源文件设为只读；WAV16/24/float32 解码逐样本完全相等，实际 44.1/48/96 kHz 和单/双声道保持；强制分块后总帧数吻合。外部 MP3 为 132,300 帧 / 44.1 kHz，M4A/ADTS 使用实际解码帧数并记录独立媒体身份，不套用自产成品的已知原长度。

不足磁盘在创建 PCM 前拒绝，取消清理自身半成品，准备期间原文件变化不会发布 ready。清理遇到未知文件或指向外部目录的 junction 明确拒绝，所有原文件 hash 保持。测试本身仅操作隔离夹具；没有修改用户原文件或正在长测的 preview.22 包。

持久化及窄仓库的后续增量见下方；ImportService 队列/取消/重建/来源变化与产品界面仍待接入。这些基础检查不等于 M12 产品验收。
