## 结论

Trace 的核心工作流已经建立：系统声音监测、独立 REC、60 秒内存历史、统一时间轴、历史表头、文件/选区回听、三种格式、导出和恢复。下一步最有价值的是补齐状态反馈、历史导航和文件交付中的断点。

保留用户已经确定的统一画布、中文“实时”、图标走带、三个时间轴图标和紧凑布局。推荐主要通过正确的状态、悬停说明、上下文菜单、快捷键与可展开详情提升体验。

## 一、优先修正的功能与交互问题

### F01 · P1 · 分析取消后的状态与重试未形成完整流程【已复现】

现象：

1. 打开 120 秒文件，在 hashing 阶段取消该分析。
2. 任务已为 cancelled，但画布仍显示“准备波形…”，状态栏仍为“分析中…”。
3. 对同一来源重新分析，新任务已 ready，当前 playback 仍引用旧的 cancelled analysisId。
4. 必须重新打开文件才会绑定可用结果。

影响：用户无法区分等待、取消与失败；正常重试后仍以为软件卡住。

建议：

- 对 queued / hashing / analyzing / ready / cancelled / failed 分别呈现真实状态。
- 在画布原位置提供继续分析/重试，不额外增加常驻工具栏。
- 重试同一资产时更新当前视图的分析引用，保留游标、窗口和选区。
- 更新引用时继续校验来源与代次，避免旧任务覆盖新文件。

依据：src/trace/renderer/App.tsx:214；src/trace/renderer/Timeline.tsx:162；src/trace/playbackService.ts:185；src/trace/analysisService.ts:21。取消路径已动态验证；失败分支存在同样的显示条件，但本轮未单独注入失败。

验收：取消不再显示进行中；同一文件原位重试成功后显示恢复，不要求关闭重开。

### F02 · P1 · 顶部文件格式显示了内部解码格式【已复现】

现象：ffprobe 验证文件为 pcm_s16le / 48 kHz / 16-bit；资料库也记录 pcm16；打开后顶部却显示“48 kHz 双声道 Float 32”。

原因：文件视图复用了回放快照 format，暂停时该结构描述内部 float32 PCM，而非磁盘资产原始格式。

影响：作为录音和分析工具，这会让用户误判保存位深；与设备选择框相邻，也容易混淆采集设备格式与当前文件格式。

建议：来源行始终明确设备的实际采集格式；文件标题/详情显示当前资产真实的 WAV/MP3/AAC、采样率、位深或码率。内部解码格式放入诊断信息。

依据：src/trace/renderer/App.tsx:200、260；src/trace/playbackService.ts:178。

验收：PCM16/PCM24/Float32/MP3/AAC 打开后，格式说明与实际资产一致；切回实时显示当前采集设备格式。

### F03 · P2 · 选区建立后缺少清除入口【已复现，属于交互缺口】

实测：选区 76800–268800 帧在按 Escape、点击选区外、执行“波形复位”后均保持；当前协议和工具栏也未提供清除命令。保留选区本身是合理行为，但需要一个明确的退出方法。

影响：选区统计一直占位，导出默认仍使用选区，用户需要重新打开来源才能彻底清除。

建议：

- 时间轴右键提供“清除选区”，配一个不冲突的快捷键。
- 起止位置和时长可在选区悬停或轻量弹层中显示，保留现有简洁主界面。
- 可补充键盘微调两端，避免恢复之前已删除的常驻起止输入栏。
- 清除选区时同步关闭循环、撤销相应独立统计和默认选区导出。

依据：src/trace/renderer/Timeline.tsx:100；src/trace/renderer/App.tsx:178；src/trace/playbackService.ts:126。

验收：清除后 selection=null、loop=false；导出默认整段；录音/暂停的 Escape 语义保持清晰。

### F04 · P2 · 局部放大后缺少横向浏览手段【实现检查 + 运行核对】

当前波形手势只有定位/选区与两种缩放；Shift+滚轮被忽略，没有横向滚动条、拖动画布或概览导航。

实测：120 秒文件放大到 50–55 秒，Shift+滚轮前后窗口都为 2400000–2640000 帧。该手势尚未承诺支持，本项是易用性建议，不将其描述为已实现功能失效。

影响：长文件需要不断“复位 → 找位置 → 再放大”，很难顺着相邻音频检查。

建议：优先实现 Shift+滚轮平移或中键拖动；需要时再加细窄的全局概览导航。平移不改变游标和读数，跟随播放与手动浏览的切换保持一致。保留现有 Ctrl+滚轮时间缩放、普通滚轮倍率规则。

依据：src/trace/renderer/Timeline.tsx:133；src/trace/renderer/App.tsx:233；src/trace/playbackService.ts:155。

验收：在任意局部时间窗能连续向前/后浏览；文件边界钳制正确；两张图共轴。

### F05 · P2 · 实时状态下快捷键与播放按钮不一致【已复现】

实测：实时已有缓存、播放按钮启用、焦点不在输入控件时，按 Space 后 playback 仍为 null。按钮能打开并播放缓存，但快捷键只在已有 playback 上工作。

建议：按钮与快捷键共用同一组操作语义；Space 根据状态播放缓存或暂停，保留录音中禁止声音回听的约束。补查修饰键、长按重复与焦点行为，避免全局快捷键抢占输入。

依据：src/trace/renderer/App.tsx:178、292。使用说明已经限定为“已选历史/文件”，因此这是可预期性提升，不是文档承诺被违反。

验收：同一状态下按钮和快捷键结果一致；弹窗和输入框内仍遵循焦点规则。

### F06 · P2 · 导出重复设置与交付步骤偏多【已复现 + 流程检查】

实测：导出对话框改为 WAV，关闭再打开又回到 MP3。初始化固定为 MP3 / 48 kHz / 192 kbps，与上次选择和当前来源无关。

当前导出先进入 Trace 会话，再由“另存副本”交付到目标目录；流程可靠，但高频导出需要多次操作。

建议：

- 记住最近使用的导出参数；允许少量用户预设。
- 首次 WAV 导出可默认跟随来源；有损格式按现有支持范围处理。
- 导出前明确当前文件、选区/整段与时长。
- 可在一个导出流程中选择交付位置，同时明确 Trace 管理副本与外部副本的归属。
- 主界面只给简短的进行中/完成反馈，详细进度仍留在文件列表。

依据：src/trace/renderer/ExportPanel.tsx:10；src/trace/main.ts:269、276。

验收：重开参数不意外变化；选区范围清楚；目标文件可直接定位；覆盖/同名冲突继续安全处理。

## 二、核心体验的进一步提升

### F07 · P2 · 把精确历史的有效范围呈现在时间轴上【实现确认 / 设计建议】

现状：监测保留约 60 秒；录音可显示全长概览，但精确浏览只覆盖当前连续段最近 60 秒。点击更早位置由 HISTORY_OUTSIDE_BUFFER 提示，完整历史需结束后打开文件。历史检查会固定一份缓存，后台监测继续。

建议：在全长概览上以很轻的底色或边界标出当前可精确检查区域；不可用位置悬停说明，减少先点击再报错。来源标题短标签区分“实时 / 固定缓存 / 文件”，可显示距实时位置的偏移。

进一步完整浏览正在录制的早期部分，需要从已完成写入的磁盘段增量读历史，属于后续功能和架构任务；不以扩大无限内存缓存解决。

依据：src/trace/main.ts:120；src/trace/renderer/App.tsx:269；src/trace/userErrors.ts:3。

### F08 · P2 · 文件列表从资产明细转为录音管理【实现确认 / 设计建议】

已经具备：搜索、分页、磁盘状态刷新、移至回收站、失效项清理、成品独立管理。外部另存副本独立管理已有提示，不应将其删除当成原会话成品损坏。

提升方向：

- 一条录音优先显示名称、时长、格式、状态和默认回听/查看动作。
- 原始文件、各成品、分段、分析状态放到可展开详情。
- 支持录音重命名、按日期/状态筛选、批量清理失效记录；真实删除继续明确范围。
- 分开显示音频占用与可重建缓存占用，提供“仅清理缓存”，避免用户手动删错。
- 保存目录与资料库范围应分开说明：当前选择新保存目录会清空并重新扫描当前 takes 映射，旧文件未删除但列表会换库。
- 当前默认名称取 createdAt.toISOString()，去掉时区标识后放入名称；在 UTC+8 环境可能比本地时间早 8 小时。建议面向人的名称/日期按本地时间，元数据继续保留 UTC。

依据：src/trace/renderer/App.tsx:61、314；src/trace/renderer/ExportPanel.tsx:32；src/trace/recording.ts:78、96。

验收建议：50+ 录音和多次导出时仍可快速定位；改保存目录不会被误认为丢失旧录音；删除与仅清缓存可区分。

### F09 · P2 · 录制前后给出必要的确定性反馈【实现确认 / 设计建议】

现状：文件错误、保留策略与后台转换有基础处理；主工作台缺少简洁的“刚才录到哪里、已完成还是正在生成成品”的结果确认。磁盘容量没有用户可见的预检/预计剩余时长入口。

建议：

- 第一次录音前可完成目录准备，减少抓录瞬间才弹出目录选择。
- 录音设置中显示保存位置、可用空间和按当前实际写盘格式估算的剩余时长。
- 停止后给短暂的“已保存 / 正在生成成品”反馈，带“查看 / 打开目录”，保持实时画布。
- 异常断开突出“正在重连、录音是否继续、已保存哪些部分”，恢复后留下可定位的中断记录。
- 明确录音时关闭窗口的产品行为。当前关闭会结束录音并完成收尾；可提供可配置的录制中退出保护，不对所有普通退出增加弹窗。

依据：src/trace/main.ts:152、235、419；src/trace/renderer/App.tsx:287、298、319。磁盘容量本轮仅检查实现和界面，未做低空间故障注入。

### F10 · P2 · 异常应该给出能执行的下一步【实现确认 / 设计建议】

现状：已有用户错误映射、文件列表详情、恢复入口；但主画布上若存在 file.error，多数情况统一显示“回听输出不可用”，输入错误则统一提示重新连接，具体错误很难从界面带出来。

建议：保留一句短提示，配“重试 / 重新分析 / 定位文件”等与失败原因对应的动作；折叠详情可复制版本、错误码、设备格式与相关状态，默认不包含个人录音或完整个人路径。可恢复录音在启动后给轻提示直达恢复项。

依据：src/trace/renderer/App.tsx:287；src/trace/userErrors.ts；src/trace/renderer/ExportPanel.tsx:50。

### F11 · P3 · 增强分析结果的可操作性【功能建议】

已支持 M/S/I/LRA/TP、目标响度线、整段与选区统计。下一步可以增加：

- 电平过载保持及一键清除，减少短瞬态被错过。
- 从 MAX TP/过载事件直接跳到对应时间位置。
- 将一次选区统计复制为简短文本，便于工作记录。
- 在目标线已开启时给出可选的目标偏差值。

先明确各数值属于本轮、游标前缀、整段还是选区，再增加显示。不要用平滑或插值改变可重复历史数值。

依据：src/trace/renderer/App.tsx:36、278；src/trace/renderer/DisplaySettingsForm.tsx:8。

## 三、可选择的后续功能扩展

以下没有被认定为当前版本缺陷，也未获实施授权：

1. **保存刚才的缓存**：对已固定的最近 60 秒/选区执行显式保存；平时仍仅在内存中保留有限音频。适合错过 REC 的临时抓录。需定义缓存保存的文件统计语义，不能直接把监测起点累计 I 当作新文件整段 I。
2. **打开外部音频文件**：让分析器可独立服务既有素材；优先支持已具备处理链的 WAV/MP3/AAC，以只读来源和独立缓存接入统一画布。
3. **少量人工标记**：记录关键瞬间并快速跳转，用于长录音检查；复杂剪辑、插件宿主和多轨工程仍按产品范围单独评估。

优先级建议：前两项根据“错过录音后的抓取”与“已有音频的分析”哪种更常见择一推进，不同时扩大范围。

## 四、发布准备与证据缺口

这些是验证未闭合，不代表已证实的音频错误：

- 真实 96 kHz 采集硬件。
- 物理拔插、驱动/DAW 格式变化全矩阵。
- 混合系统 DPI 跨屏切换。
- 独立干净 Windows/VM。
- 正式 A01–A14 全部发布门禁。

当前仍按开发预览定位。此前工程和主观验收继续有效，但不扩大解释为上述专项通过。

## 五、建议推进顺序

### 第一批：状态准确与交互完整

F01 分析取消/重试、F02 格式信息、F03 清除选区、F04 横向导航、F05 快捷键一致性。

退出条件：无需重开文件恢复分析；磁盘格式说明准确；局部历史可以连续浏览；选区可以明确退出；同一操作的键盘和按钮一致。现有历史快照一致性与 REC 独立性回归继续通过。

### 第二批：录音交付与文件整理

F06 导出偏好/范围/交付、F08 文件列表与本地时间、F09 录音完成反馈、F10 错误下一步；同步完成 F07 有效缓存范围提示。

退出条件：一次录音从开始到交付可直接完成，用户知道文件在哪里、哪些可删、哪些还在处理。

### 第三批：选择一个高价值扩展并补发布专项验收

缓存保存或外部文件导入择一；发布门禁按真实素材与硬件条件独立验收。

## 工程跟进备注

源码发现 library.remove 在关闭当前查看文件后，只要 monitoringRequested 为真就调用 startDevice，没有复用 resumeInput 的健康采集检查（src/trace/main.ts:176–185）。需补一个隔离回归，确认“仅删除所查看文件且后台正健康监测”不会重建采集周期或清掉缓存。本轮未操作原生删除确认框，不把该推断列为已复现缺陷。

本轮没有实施上述修复。下一开发会话应从第一批开始，并保留当前基线标签。
