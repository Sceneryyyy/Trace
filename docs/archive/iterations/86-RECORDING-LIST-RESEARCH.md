# 86 · 录音列表调研与改版建议

日期：2026-10-15。对照源码 `6b37ed4` / preview.33；用户希望下一阶段聚焦已有录音的播放列表，先研究其他播放器、录音机的做法。本次是调研和设计建议，尚未改动产品界面、播放逻辑或版本。当前阶段以“找到录音 → 回听 → 查看分析”为建议主线，具体操作偏好待用户反馈。

2026-10-15 后续：用户已授权按任务单继续实施。L86-01～03 的实现、实际验证及待验边界见 [87](87-RECORDING-LIBRARY-ITERATION.md)；下方为实施前调研快照。

## 现有列表的问题

以下来自当前源码检查，未把静态观察当成实际用户测试：

| 观察 | 实现位置 | 对使用的影响 |
| --- | --- | --- |
| 导入说明、刷新素材、录音目录、搜索/状态/起止日期、数量/容量/刷新/清理均在列表上方 | `RecordingLibrary.tsx` | 找到第一条录音之前需要扫过较多维护信息 |
| 普通录音默认显示三行身份/状态、查看/设为参考/导出及详情入口 | 同上、`styles.css` | 行高与按钮数量偏多，名称和时长不够突出 |
| 展开详情后，每个文件角色再次出现查看/导出/分析，成品另有操作 | `FileAnalysis`、`ExportItems` | 一个 take 的多个物理文件与主操作混在一起，容易重复选择 |
| “查看”只打开暂停的文件上下文；回听还需使用工作台走带 | `main.ts` 的 `file.open`、`PlaybackService.open` | 列表没有直接且明确的回听入口；不能简单把“查看”改名为“播放” |
| 打开成功后关闭弹窗；再次打开会重建列表组件 | `App.tsx` 的 `run`、条件渲染 | 搜索、日期、已加载数量等局部状态丢失，反复切换文件的成本高 |
| 录音和导入素材上下排列，各自首次 50 条，“显示更多”追加 50 | `RecordingLibrary.tsx`、`ImportedLibrary.tsx` | 不是页面切换或虚拟列表；持续展开后 DOM 会增长，两个来源还各有一套行呈现 |
| 尚无独立的行选择状态，也无当前载入/正在回听的行标识 | 两个列表组件 | 很难从列表直接判断正在分析/回听哪条录音 |

现有能力需要保留：名称/日期/状态检索、恢复、分段/成品选择、缺失文件提示、采集质量、重命名、参考、导出、缓存维护和各类移除语义。精简应通过信息分层完成。

## 调研对象与实际证据

检查四个项目的公开源码；KRecorder、Dopamine、Strawberry 另查看官方页面或仓库截图。没有运行这些应用，没有做性能横评。截图属于各项目发布时的示例，不能证明今天所有平台的界面一致。固定提交、文件 blob 与下载 SHA-256 见 [来源清单](../../research/2026-10-15-recording-list-sources.json)。

### KRecorder：让录音名称和时长成为主角

- [官方应用页及截图](https://apps.kde.org/krecorder/)：列表突出名称、日期、时长，回听使用专门区域。
- [RecordingListDelegate.qml](https://github.com/KDE/krecorder/blob/b2f50f70320647f85a96ea75a8ac0df6f4a32a3e/src/contents/ui/RecordingListDelegate.qml)：普通行只呈现主要信息；导出、重命名、回收站按钮在编辑模式显示；宽屏下当前录音有高亮。
- [Main.qml](https://github.com/KDE/krecorder/blob/b2f50f70320647f85a96ea75a8ac0df6f4a32a3e/src/contents/ui/Main.qml)：根据宽屏状态切换单列/固定分列呈现。

适合 Trace：把“名称、时长、录制时间”放在首层，把文件维护放到详情或更多菜单；宽屏下保留列表以便切换。KRecorder 的移动端尺寸、整套编辑模式和独立播放页不直接照搬，Trace 继续使用已有分析工作台。

### Dopamine：选中和正在播放分别表达

- [项目与界面示例](https://github.com/digimezzo/dopamine)：列表与统一走带共存。
- [track.component.html](https://github.com/digimezzo/dopamine/blob/c1d4e8f5936e1c5734944613c48c889c91a67771/src/app/ui/components/collection/track/track.component.html)：选中背景与正在播放的标题颜色/指示器分开，支持紧凑呈现。
- [collection-tracks-table.component.html](https://github.com/digimezzo/dopamine/blob/c1d4e8f5936e1c5734944613c48c889c91a67771/src/app/ui/components/collection/collection-tracks/collection-tracks-table/collection-tracks-table.component.html)：列排序、定位正在播放项、上下文菜单、双击播放、虚拟滚动；表格视图 `itemSize=28` 是其实现值，不是 Trace 的推荐尺寸。

适合 Trace：明确区分键盘焦点、选中、已载入、正在回听；让菜单承担低频操作；大列表按测量结果选择分页或虚拟化。专辑/艺术家/评分/收藏等音乐库字段不适合作为录音默认列。

### Strawberry：列表信息可比较，当前位置可找回

- [官方界面示例](https://www.strawberrymusicplayer.org/)和仓库 `data/screenshot/screenshot.png`：名称、时长等字段对齐排列，走带统一放置。
- [playlistview.cpp](https://github.com/strawberrymusicplayer/strawberry/blob/d45cfa1604b959530822e9642061371c86b37682/src/playlist/playlistview.cpp)：独立处理上下文菜单、键盘播放和定位正在播放项等行为。
- [playlistfilter.cpp](https://github.com/strawberrymusicplayer/strawberry/blob/d45cfa1604b959530822e9642061371c86b37682/src/playlist/playlistfilter.cpp)：检索通过模型过滤；排序会交给来源模型处理。

适合 Trace：对齐时长、时间等可比较字段，提供“定位当前文件”。Trace 初期仅需要少量字段；复杂列配置、多播放列表与来源模型的排序语义另评，不能把列表排序与实际回听顺序默认绑定。

### Audacious：紧凑行、搜索和键盘操作

- [官方 3.9 发布说明](https://audacious-media-player.org/news/42-audacious-3-9-released)：介绍按需搜索、列增删/移动/缩放和不干扰操作的错误呈现；这是历史引入记录。
- 当前核查的 [playlist-qt.cc](https://github.com/audacious-media-player/audacious-plugins/blob/10a90c1aa412d1ab63ec3261806719bbf6608d13/src/qtui/playlist-qt.cc)：统一行高、模型过滤、选择与激活分离，上下文菜单集中处理。
- [search_bar.cc](https://github.com/audacious-media-player/audacious-plugins/blob/10a90c1aa412d1ab63ec3261806719bbf6608d13/src/qtui/search_bar.cc)：检索、上下移动焦点、关闭搜索并返回列表。

适合 Trace：列表行为保持可预测，键盘与鼠标都能找到相同操作。完整多选、拖动排序和队列能力适合后续单独评估。

补充边界：尝试访问 `GNOME/gnome-sound-recorder` 的 GitHub 地址返回 404，未将搜索得到的旧 GNOME 设计稿算作本次已核查的现行实现。上述四项已覆盖录音机与桌面播放器两类。

## 推荐的 Trace 形态

推荐组合为 **KRecorder 的信息分层 + Dopamine 的状态区分 + 桌面播放器的紧凑列表**。以下均为 Trace 方案建议，尚未实施。

### 列表首层

宽视图建议排列：`回听 │ 名称 │ 时长 │ 录制时间 │ 状态 │ 更多`。名称可附一行弱化的格式；窄侧栏将时长/时间收成第二行。行高以 48–56 CSS px 作为原型起点，缩放和触控目标另验，不把播放器 28 px 行高直接移植。

顶栏保留搜索、排序、筛选入口、导入；类别提供“录音 / 外部素材”，默认打开录音。日期范围放入筛选面板；实际生效的筛选条件需要可见、可清除。录音目录在该类别显示简短入口，完整路径、切换与空间/清理放入管理区。

普通条目以名称、时长和日期为主，避免每条都重复“已保存”的完整说明。异常、准备/分析进度、含中断/估计补零/质量未知应保留可见标识和文字解释，不能只藏在悬停或依赖颜色。

### 主次操作

| 操作 | 建议行为 |
| --- | --- |
| 单击行或方向键 | 只选择，展示该条目详情；不自动发声或替换当前回听来源 |
| “查看分析”/Enter | 将明确选定的来源载入现有工作台，不自动发声 |
| 行内回听按钮/双击 | 显式回听该条目；准备未就绪时显示实际状态，录音期间禁用并说明原因 |
| 正在回听项再次点击回听按钮 | 复用当前播放上下文切换播放/暂停，保留游标和选区，不重新 `file.open` |
| 更多菜单/键盘菜单入口 | 重命名、导出、设为参考、打开目录、查看详情；危险操作单独分组并保留原有确认 |
| 当前文件入口 | 将当前已载入条目滚入视野；如果被筛选隐藏，提示原因并提供清除筛选 |

初期 Space 继续沿用主工作台既有播放/暂停语义；输入框、重命名表单和菜单不得误触全局快捷键。“查看分析”的键盘行为与“显式回听”不同，必须通过可访问名称及可见提示说明。

### 详情与工作台

列表只显示一份 take；详情集中说明当前采用的文件版本/格式、原始文件、连续段、成品、分析状态、采集质量与维护操作。默认来源继续遵循 `preferredSource`；多段录音或成品切换必须显示当前文件身份，不能把第一段误称整段。

建议最终使用同窗口内可收起的侧栏：选择列表与既有波形/响度/频谱画布共存；底部继续共用现有走带。侧栏是否进入现有可停靠布局系统，需在原型中评估，不先假定需要新增仪器类型。小窗口可用覆盖式抽屉，关闭后保留查询、类别、选中和滚动位置。窄屏覆盖式面板与现有模态的焦点约束分别实现。

本轮“播放列表”首先指已有录音/素材的查找与回听入口。自动连播、拖动排序、随机/循环整份列表、自定义歌单和 M3U 导出会引入持久顺序及队列规则，建议另立需求，避免把首轮精简扩展成完整音乐播放器。

## 推荐实施顺序与退出条件

| 工作票 | 顺序/内容 | 完成标准 |
| --- | --- | --- |

| L86-03 | 搜索/排序、定位当前与大列表资源检查 | 50/500/5000 条模拟数据测实际 DOM、滚动和交互；按证据选择有界分页或虚拟化；重排仍按稳定 ID 绑定选择和当前项；不能声称模拟测试等于真实磁盘/声卡验收 |

先完成 L86-01 的视觉原型和操作映射，再实现 L86-02；L86-01 中的回听位置可先作原型，产品启用须等 L86-02 完成。以上优先级只适用于本轮列表改版，不重开已经完成的 R83 P0/P1。

工程检查关注：复用现有 `file.open`/`playback.play`，以返回的真实播放 ID 和来源身份做连续操作；核查过期请求、目录/来源切换、快速点击和 REC 准备竞态，必要时才扩展命令契约。不能用延时器拼接自动播放，也不能通过 UI 隐藏缺失/不完整状态。

浏览器验收应覆盖：空列表/仅导入、长中文名称、缺失/不可读/恢复中、多段与首选成品、当前项被筛选、菜单/详情焦点回归、重命名输入快捷键、100%/150%/200% 的布局。删除录音继续回收站；外部素材移除引用继续保留原文件和成品；恢复与缓存保护语义保持。若实施播放路径变化，再跑相应播放/来源代次测试与 Windows 门禁。
