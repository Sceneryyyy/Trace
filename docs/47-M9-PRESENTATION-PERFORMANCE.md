## 功能与显示一致性

- SpectrogramPacket 带分析/频率配置键，FILE 来源可带 analysisId。主进程核对当前分析身份；renderer 在渲染时立即核对来源、epoch、分析 ID 与配置，不依赖 effect 后清空旧图。
- Timeline 的 Canvas 绘制在 layout effect 中执行，更新标签后的首个画面即应用对应数据或清空。绘制上下文与 Canvas 标记在实际 requestAnimationFrame 采样中一致。
- 同一来源的缩放/平移和尺寸变化可以保留仍有正确坐标的图像，等待新分辨率数据。颜色和色阶不改变测量身份。
- 当前来源读取失败时出现“重试”；重新请求不会换来源。错误按上下文保存，不串到新来源。隐藏/恢复暂停文件后会续建查询所有权，点查询仍可使用。
- 单声道素材沿用 Mid/Side/右声道时说明需要双声道，并提供切回默认声道的入口；不计算伪造的立体声结果。

## 性能改动及正确性

1. **着色表复用。** 使用 4096 级色表，直接填充有界 RGBA 数组；每个像素不再创建颜色对象。与旧颜色计算的差异至多一个 8-bit 色级，原始 dB/状态/方向不变。
2. **新增列计算。** 末尾时频块增长时只请求新的 FFT 列，再与已验证的旧列拼接；不反复计算旧的全部 64 列。旧数组保持不变。
3. **频率与时间最大值复用。** 合并重复的频率行，构造每块的区间最大值树和状态前缀计数。像素查询仍精确汇总其实际覆盖的原始列/bin；缺口、部分覆盖、静音和过期范围保持区分。
4. **显式资源上限。** 原始块与派生结构共同计量。FILE 原始块上限 48 MiB，二者合计不超过 64 MiB；LIVE/REC/Replay 原始块上限 96 MiB，二者合计不超过 112 MiB，为工作中的块和显示结果留出预算。派生缓存以弱引用关联原始块，不阻止其释放，取消/换源清空对应结构。
5. **及时请求与渐进结果。** 实时范围随时间轴快照触发，并以 33 ms 检查补充刷新；同一范围不重复请求。旧工作仍按代次合并/取消，冷查询先发布可用的新近部分。音频计量仍由原生完整音频驱动，不使用 UI 定时器计算音频。

35 组固定随机输入用逐像素原始扫描作独立对照，覆盖大 uint64 原点、部分时间边界、四类掩码和静音；最大值、掩码及覆盖比例逐项一致。各 FFT 大小的原始/派生总量保持上限。
