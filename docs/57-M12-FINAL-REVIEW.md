# 57 · Trace M12 工程交付与同维度复评

日期：2026-09-17。最终候选：**Trace 0.1.0-preview.25 / Windows x64**。

结论：M7–M12 计划内功能已完成工程交付。按 37 原八维、原权重和以 0.5 为主要粒度的尺度，本次专家评估的 **加权分 8.6500、算术均分 8.6875，均严格超过 8.5**。这是对指定工作流、当前功能和界面的主观评估，不是算法精度百分比、用户实验结论或正式认证。

## 1. 固定评价口径

沿用原对象：具备音频基础，希望在同一窗口理解电平、响度、频率、声像和历史，并按任务调整仪器的使用者。10 分代表非常完整、清楚且适配工作流；8 分表示成熟但有明确改进点；6 分表示可用但有明显限制。未调整原权重或基线分数。

评价依据包括 M7–M12 已交付实现、实际 Windows 流程、100%/150%/200% 进程缩放、最小窗口截图、同源/跨采样率/选区对照、30 分钟资源任务，以及录音/报告/原文件完整性。人工操作脚本和专家截图复核不等于用户研究；原 Insight 2 评估仍来自当时手册与图示，没有在本轮重新进行竞品宿主实测。

## 3. 工程证据与候选关系

### 完整功能与资源

- preview.24：40 阶段 / 204 JS 合并短门禁通过。第一次显隐脚本仍断言 7 个仪器，修正为实际 8 个；原失败保留。后续在相同 ASAR/native 上补完显隐、旧导航、包/ZIP/重定位，见 final-1789605251771 与 final-tail-1789605705613。
- 30 分钟真实 GPU/捕获/比较流程 **1800.128 秒通过**：120 次采样、29 次显隐、33 次 A/B 切换、25 次报告生成、9 份导出、至少 10,608 组参考频谱。无丢帧或仪器错误，未发生 hash 重试。工作集峰值 798.63 MiB、主进程 417.82 MiB、报告 worker 103.92 MiB；尾段平均相对原基准段下降约 115.13 MiB，原阈值未放宽。
- 事后录音 **14,402,880 帧 / 300.060 秒 / 48 kHz 双声道 PCM24**，头、帧边界和 SHA256 与清单一致；9 份报告均四文件完整、每份 1600 条声道读数、末帧 384000，夹具源 hash 保持。证据 resources-1789606251763/report.json 与 recording-integrity.json。
- 多格式参考原生矩阵 4 项通过：单声道 96k WAV、44.1k MP3、48k M4A、32k ADTS、真实较短 B、静音与独立选区。证据 reference-matrix-1789606680822/report.json。这里的 96k 是文件分析，不是实际声卡 96k 采集。

### 最终界面收尾候选

preview.25 仅修正参考面板的单声道/静音说明，以及由当前数据推导悬停读数、绑定变化清除旧悬停；另更新版本/说明。

- 包级对照验证了 8 个 main/worker/preload JS，除产品版本字面量外与 preview.24 完全一致，原生模块字节一致。证据 feedback-package-1789607501552/report.json。因此复用 24 的音频/主控/资源证据，明确不将 24 长测改写成 25 全量重跑。
- preview.25 的独立反馈渲染 4 项、参考三组缩放、包审计、实际打包录音/编码/重开、ZIP 逐文件与中文路径重定位均通过，9 阶段报告 feedback-final-1789608070776/report.json。
- 悬停与状态的独立渲染使用明确标记的测试数据；实际音频正确性另由原生矩阵和包内流程证明。
