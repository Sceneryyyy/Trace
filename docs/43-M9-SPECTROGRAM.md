# 43 · M9 时频缓存与 2D 声谱图设计

2026-09-16。M8 功能提交 3a8bda1，preview.11 的长资源门禁仍在独立包中运行。本阶段先建立时频瓦片（分块数据）的计算、格式与验证，再接入服务和界面；尚不能宣称 2D 声谱图已交付。

## 1. 共同数据与精度

- 与 M8 使用同一周期 Hann、实际采样率、声道模式及单边幅度标定。声谱图记录单个 FFT 窗的值，不默认套用频谱曲线的时间平均或峰值保持。
- hop=min(N/4, floor(rate/50))，FFT 512–16384。每列记录明确的窗结束帧；其音频范围为 [end-N,end)。不进行未来样本读取或隐式零补齐。
- 原生一次最多 64 列，完整 0..N/2 频点；最大输出约 2.1 MiB。只读取 N+63*hop 的短 PCM 区间，不复制整文件。
- 缓存保存 Float32 **dB 幅度谱**，未着色，保留全部频点。零功率使用 -Infinity 表达真正静音；另有每列状态掩码区分未就绪/缺口/错误，不能以 0 dB 或黑色一概代替。
- log32 的量化误差目标 ≤0.0001 dB；与 M8 同窗单点对比时按此口径校核。NaN/+Infinity 禁止进入有效数据。该表示避免把低于 Float32 功率范围的有效弱信号错误变成静音。
- 2D 颜色和 M10 的 3D 高度共用这些未着色数值；配色、动态范围、相机和显示尺寸不改变缓存身份。
- 准确点查返回真实列结束帧、频点 Hz 和该频点 dB 值。显示像素可聚合多个时频单元，必须标明其覆盖范围，不能将像素聚合峰值冒充精确频点。

## 2. 时间与来源

文件以已解码/剪除首尾填充后的逻辑音频起点为 0。缓存与原文件、导出成品、解码范围分别绑定。跨分段读取继续使用 WaveSequence，不能用播放器输出或波形 min/max 反推频谱。

LIVE 的网格起点采用该 measurement epoch 的音频原点（可由 positionFrame-measurementFrames 得到）；REC 使用原生段原点和 nativeId，再映射到统一纳秒轴。固定 Replay 的网格相位保持原 originFrame：首个完整本地窗结束为 N+((hop-originFrame%hop)%hop)，与原实时网格对应。普通外部文件/文件资产采用 N+j*hop。

每个显示请求包含来源身份、配置键、请求代次和时间/频率范围。已经完成的同来源瓦片可复用；旧请求不能覆盖新视口。新来源、新 epoch、算法参数或真实文件身份变化使相关请求失效。主游标保持统一；点查/点击使用对应的实际列时间。

仅包含可得 PCM 的范围才可分析。录音早期区域在当前精确缓存外时保留明确不可用/概览状态，停止后打开文件获得完整历史。缺口不能被插值或涂成正常静音。

## 3. 原生、缓存与显示分层

1. Native Tile：从有界 ROI 或 WaveSequence 读取音频，复用 M8 已验证计算，输出未着色 log32、列掩码和格式/帧信息。与瞬时仪器共享至多两个任务名额。
2. SpectrogramStore：每次最多一个低优先级瓦片请求，留出瞬时表头的计算名额；取消/来源变化后不补写被删除来源的目录。
3. 已保存文件按配置键在其应用持有 cache 根下保存分块数据；使用内容/算法/配置身份、长度和 SHA256 检查，临时写入后原子发布。坏块隔离并重建，原音频不修改。
4. LIVE/REC/固定内存回看只用有界内存缓存，未录音时不因声谱图而产生音频或频谱临时文件。
5. View：原始瓦片与显示栅格分开。可视区至多 1024×512 单元（约 2 MiB），按时间/对数频率聚合，记录显示分辨率；精确点查仍访问原始频点。
6. 前端共享已有时间窗、游标、选区与来源。后台分析未覆盖区域显示准备进度/缺口，其他已就绪仪器不等待整文件扫描。

## 4. 容量与调度

- 最大 FFT 在 96k/20ms hop 下 60s 原始 log32 约 94 MiB，实时缓存预算 128 MiB，限制在当前可查看约 60s；过期瓦片淘汰。
- 文件原始瓦片按需读写，内存预算 64 MiB，磁盘容量随实际文件长度增长并进入缓存管理。仅查看视口即可先得到该区域，不要求先把全文件读入内存。
- 单次原始/显示 IPC 均 ≤4 MiB；每个来源有界待决请求，旧窗口合并/取消；M8 瞬时测量优先，录音写盘优先于所有派生缓存工作。
- 配置切换不同时保留无限套 60s 缓存；预算按所有当前上下文合计执行。
- 无法取得完整 FFT 窗时显示未就绪，不通过缩短 N 或改变窗函数“加速通过”。

## 5. 本阶段退出检查

- 原生列与 M8 同窗单点数值一致，覆盖 DC/Nyquist、低电平、分块起点、EOF、NaN/缺口和大帧号。
- 单块大小与列数上限可判定；损坏/错误身份/截断磁盘块不可被接受。
- 同一来源反复/反向定位、配置变化、取消、旧回包淘汰、不同文件格式独立分析。
- 单音/扫频/脉冲的时间和频率位置真实；2D 与波形共轴，选区及跟随行为明确。
- 长文件按窗口读取；LIVE 运行后保持容量上限；主进程记录观察和录音帧数不受加载/缩放影响。
- 交付 2D 面板、设置/帮助、独立包与 A17/A20/A26 证据。当前仅在建立数据底座，服务/面板尚未完成。

## 数据底座当前验证

已实现 SpectrogramTile 原生计算及 128 字节头的单块二进制编解码（未接入持久化服务/界面）。每块保存未着色 log32、列掩码、帧/格式和来源摘要，并以 SHA256 覆盖元数据及负载。原生 CTest 15/15，tile 20 个场景通过；JS 编解码 3 项通过。最大 64 列 / FFT 16384 原生计算约 62.4ms，输出小于 4MiB；这是单块冷计算，不是整条显示链路指标。

代码中的 tile.firstFrame 表示第一列 FFT 的结束帧，区别于 PcmWindow.firstFrame 的 PCM 缓冲起点；后续接口命名需明确这一点。覆盖低电平有限数值、静音/缺口/错误、列数上限、64 位帧号、错误身份、截断和数据损坏。报告 artifacts/m9/tile-results.log；构建/CTest 记录 tile-build-2.log。
