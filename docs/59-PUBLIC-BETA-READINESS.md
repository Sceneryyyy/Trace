# 59 · 公开测试准备度评估

日期：2026-09-17。评估对象：preview.26 / 66dbbdd，Windows x64 便携包。

## 1. 放行结论

**暂不建议直接开放给不熟悉项目的用户下载。** 功能已足够开展小范围试用；应先修复重复启动覆盖设置的问题，补齐独立环境、异常支持和分发材料，再组织邀请制测试并逐步开放。

这里将“公开测试”定义为：用户无需开发者陪同即可下载、启动、完成主要任务；遇到问题能保护已有音频并提供有效反馈。它不要求全部未来功能、全部声卡或全部制式均支持，但已承诺的范围必须有证据。

57 的 8.65 是功能/工作流专家评分，不是发布就绪度。用户实际找不到布局入口，说明可发现性仍缺独立用户证据；本轮没有调整原分数，也不以原分数放行公测。

## 3. 本轮新发现

### B01 · 公测阻断：重复启动可覆盖设置【实际复现】

使用 preview.26 的两个独立进程，共享仅供测试的配置目录，关闭监测且不录音/回听：

1. A、B 同时打开，初始“录音中退出确认”为开启。
2. A 将其关闭，磁盘配置已成功保存为 false。
3. B 没有修改该设置，只执行正常退出。
4. 磁盘配置被 B 写回 true；仍打开的 A 显示 false。

报告：`artifacts/public-beta/instances-1789622598615/report.json`，结果 issue-confirmed。测试进程已关闭，未操作用户配置或录音。

实现依据：`src/trace/main.ts` 未使用单实例保护；`savePreferences()` 写入该进程的完整设置快照，退出再次保存。`PreferencesWriter` 的原子写入和串行队列只协调本进程。复现证明设置回退；其他共享元数据的冲突风险属于推断，本轮没有复现音频损坏。

建议：当前产品采用单实例，重复打开时激活已有窗口；同用户、不同解压目录/旧新版本也不能并发写同一数据根目录。若将来允许多实例，必须设计独立存储及跨进程所有权，不能只加文件写入重试。

验收：连续重复启动、两个版本交叉启动、已有实例最小化/录音/编码时再打开，均不产生第二个共享写入者；布局、退出确认和录音目录无回退。

### B02 · 公测前补齐：崩溃后的提示、诊断与恢复【实现检查】

已有录音日志/恢复逻辑、轮询异常收尾、退出等待和固定字段诊断复制，应保留。检查 Trace 入口未发现 `render-process-gone`、`child-process-gone` 的统一处理，React 未发现错误边界；主进程启动失败主要写 console 后退出。当前复制诊断只有当前状态，缺少重启后的故障历史及新仪器/导入/报告任务上下文。

这不表示现有录音恢复失效，也不表示本轮复现了白屏；属于故障发生后用户可操作性与支持证据的缺口。

建议：界面故障提供受控重载/退出；主进程致命异常记录后安全退出，禁止捕获后继续未知状态；重启提示可恢复录音。增加有大小/数量上限的本地事件日志和手动导出诊断包，包含版本/构建、系统/图形基础信息、错误码与近期任务状态，默认剔除路径、设备身份、文件名和音频。提供 Trace 专用反馈入口与模板，用户主动选择附件。

验收：在隔离素材上注入渲染进程退出、worker 失败、进程终止/再次启动，能明确区分录音仍在进行、已停止或需恢复，并能拿到脱敏报告。不得将正常恢复误写成全部音频完整。

### B03 · 公测阻断：独立电脑与承诺范围验收【证据缺口】

至少选一台未安装开发工具的 Windows 11 x64 普通用户环境，完整验证解压、启动、选择设备、监测/录音、回听、三格式导出、重启；另选核显/普通笔记本覆盖 GPU 差异。Windows 10 等环境只有验证后才列入本轮支持范围。

实际硬件优先覆盖内置输出与 USB 声卡、44.1/48 kHz、拔插、默认设备变化、DAW 占用/释放、睡眠恢复、只读/空间不足目录。若声称 96 kHz 采集受支持，应取得真实设备结果；否则明确列为待验证实验范围。失败不能用正常静音或完整录音提示掩盖。

这是新增建议的公测门槛，不是对未运行测试的通过声明。既有模拟/原生单元故障检查继续有效，不能替代目标硬件验证。

### B04 · 公测前补齐：可信分发、对应源码与依赖复核【包/源码检查】

当前 `Trace.exe` 的 Authenticode 状态为 NotSigned；便携 ZIP 可用于 Beta，并不必须先做安装器或自动更新。公开分发需要固定版本下载地址、校验值、适用系统、已知限制、手动升级/回退说明，并测试浏览器下载后的首次运行。签名强烈建议，但不承诺签名后一定没有信誉提示。[Electron 签名说明](https://www.electronjs.org/docs/latest/tutorial/code-signing)

Trace 基于 GPL-3.0 的 Prism 修改，当前包包含许可文本，但上游仓库不能代表 Trace 的修改源码。公开分发前应在下载处提供匹配版本的对应源码及必要构建脚本/依赖资料；这不意味着必须选择 GitHub，可使用源码归档等合适方式。[GPLv3 第 6 节](https://opensource.org/license/gpl-3.0)

FFmpeg 锁定构建启用了 GPL/version3，且静态包含多项依赖；目前有二进制哈希、配置与上游提交，仍须核对该分发构建及依赖的对应源码和许可材料，不能把其当成纯 LGPL 构建。[FFmpeg 官方许可说明](https://www.ffmpeg.org/legal.html)

源码已经开启 contextIsolation/sandbox、关闭 Node integration、限制导航/新窗口、检查 IPC 来源，并设置 CSP。公测前仍应检查锁定 Electron/FFmpeg/运行依赖的支持状态与安全公告、损坏媒体输入和打包调试入口。当前未完成漏洞审计，未声称发现具体 CVE；根据证据处理必要补丁，不整树盲目升级。[Electron 安全检查表](https://www.electronjs.org/docs/latest/tutorial/security)

### B05 · 测量承诺需要补证据【专项待验】

已有生成信号、TP 矩阵、跨采样率与文件历史重复性证据；原始 EBU 官方测试集仍未跑完。公开宣称符合某制式前，完成所需官方参考素材与容差检查；与 Insight 2 对照时统一分析起点、声道、门控及范围。竞品目视读数不能代替正式参考值。

可以发布限定范围的实验性分析工具，但应明确计量验证范围，不能让报告的“达标”被误解为软件本身已经认证。外观、稳定性或功能数量不抵消已知测量误差。

## 4. 首轮试用前的易用性改进

1. 沿用任务预设作为入口，避免首次就堆满八个仪器。打开多个仪器后优先让用户选择合适预设；手动排列保留用户控制。
2. 显示与帮助补齐新仪器操作、来源与统计范围说明；当前内容主要覆盖录音/波形快捷键。提示按需出现，避免常驻大段说明。
3. 检查“实时 / 历史”“查看 / 发声回听”“本轮 I / 整段 I / 选区 I”“频谱 / 声谱图”“当前布局 / 命名预设”能否被新用户正确区分。
4. 统一首次目录准备、无设备/无声音、分析等待、取消/错误和缺口的可执行下一步。
5. 提供一个简短首次任务清单和反馈模板；不强制引导向导，不自动收集录音。

建议先找五名未参与开发的音频用户，无口头指导完成录音导出、60 秒历史/缓存保存、调整布局、范围报告和 A/B。每个核心任务至少四人独立完成且无文件/范围误判；这是本次建议的内部放行指标，不是行业统一标准，也不是统计意义上的用户研究结论。

| 顺序 | 工作 | 放行条件 |
