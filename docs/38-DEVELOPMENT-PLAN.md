## 1. 产品目标与执行口径

将 Trace 从系统声音录音与响度回看工具，发展为 **可自定义布局、所有仪器共享时间上下文的综合音频分析工作台**。

最终可以在同一窗口完成：监测 → 查看历史 → 保存缓存或录音 → 频率/声像/响度检查 → 选区复核 → 导出音频与测量结果。用户按任务选择仪器组合，不重新拆分 LIVE、FILE、HISTORY 页面。

本计划是后续需求、任务状态和阶段验收的入口。37 保留调研依据；01 说明产品范围；02–06 承载实际设计与契约；07 为任务索引；08 保留基础验收；13 记录当前唯一推进焦点。旧文档中“固定三列”“频谱不在首版”等描述属于此前版本，不能据此撤销本计划的后续目标，也不能将计划中的能力描述为当前已实现。

计划建立时未启动改造；用户现已授权持续推进至 M12 并复评迭代至均分严格超过 8.5，按阶段提交 Git。后续进入某阶段时，先完成该阶段的前置设计和复用验证，再实现并交付。工程细节在授权范围内按证据决策，不为每个小步骤增加确认环节；影响产品范围的变化回到本计划记录。

**复评规则：**

1. 固定候选包、输入素材、配置、窗口尺寸与使用任务，先记录通过/失败及证据，再给分；不从计划文字给已实现分。
2. 每维写出得分理由、尚存差距和证据位置；没有新用户实验或竞品实机对照时，明确属于专家评估。
3. 同时报出加权分 `Σ(单项分 × 权重)` 与算术均分 `Σ单项分 / 8`；用未四舍五入值判断是否严格大于 8.5。原始两组分数与权重不因开发结果回改。
4. 未达到目标时，把扣分原因转成“问题 → 使用场景 → 改动 → 验收”的具体工作票，优先处理影响多个任务的短板；完成后用相同场景复测。
5. 数值准确性、稳定性、资源及硬件专项仍是独立门禁；不能用较高外观分抵消真实失败。缺少证据的结论标为未验证，不将其写成通过。

4. 未录音 PCM 缓存最多 60 秒；只有显式保存才写入独立音频。新分析与显示缓存也必须有界。

7. 采集/录音使用真实帧与设备时钟；原生采集线程不等待 UI、FFT 绘图、磁盘或编码器。
8. 已捕获音频与故障记录优先；不足数据、静音、缺口、错误分别表示。降低绘图细节不能悄悄改变测量精度。

10. 保留 TRACE 自有标识、字体许可和依赖来源；采用自己的图标/视觉资产。

**目标：先让现有仪器可组合，建立所有后续仪器共用的框架。**

### 4.1 任务与交付

**布局范围：**先做主窗口内停靠/网格式组织，每种仪器默认一个实例。独立浮窗、跨屏独立仪器窗口、多实例任意嵌套不在本阶段。编辑布局通过明确入口进入；退出编辑后恢复日常时间轴操作，避免拖仪器与拖选区冲突。

**预设：**M7 提供“录音回看”“响度检查”和自定义。频率/声像仪器可用后，再加入“频率诊断”“声像检查”。不以占位假仪器充实预设。

**设置分离：**布局保存位置、尺寸、可见性及纯显示参数；测量目标、影响数据的 FFT/平均窗等分析配置独立管理。以后布局若引用分析预设，应明确恢复规则，不能因切布局悄悄改变累计响度或交付目标。

### 4.2 M7.0 必须明确的设计决策

- 面板状态、全局来源/游标/选区状态由谁拥有；生命周期如何分离。
- 隐藏仪器时停止哪些绘图/订阅，哪些计量继续；重新显示如何从可用缓存补齐。
- 慢仪器的状态呈现：未就绪时明确等待，不能把旧来源/旧位置结果标成当前。
- 拖动布局、频率轴缩放、时间轴缩放、选区和键盘焦点的冲突处理。
- 布局损坏/版本不兼容/窗口变小时如何回退，且不重置录音目录或声音设置。
- 未来 2D/3D 共用数据的接口、预算归属与取消路径。
- 上游复用清单：具体文件/提交/许可、线程与内存特点、数值差异和验证缺口；复用或重写的依据。

新设计说明文件在 M7.0 创建并链接回本计划；当前不预先声称它们或新命令已存在。

### 4.3 退出条件

## 5. M8 · 频谱与立体声声场

**目标：用可核对的频率和声像信息补齐现有分析能力。**

| 任务 | 工作内容 | 交付与检查 |
| --- | --- | --- |
| M8.0 · 数值规格 | 明确 FFT 窗、hop、幅度标定、声道模式、平均/保持和时间锚点；定义相关度/平衡/余辉窗口 | 将算法与边界写入 03，数据/身份写入 04/06；在实现前固定参考值及容差 |
| M8.1 · 频谱内核与面板 | 连续曲线、平均、峰值保持、频率/幅度轴缩放/平移/复位、位置读数 | 已知单音/多音/脉冲/噪声夹具；固定配置的实时和文件结果可对照 |
| M8.2 · 立体声声场 | 相关度、左右平衡、基础 Lissajous；在同一模型上增加 Polar Sample/Polar Level | 同相、反相、不相关、单边、静音与单声道语义明确；界面有数值/范围辅助 |
| M8.3 · 历史与布局接入 | 新仪器跟随实时、固定缓存和文件游标；新增对应布局；设置持久化 | 反向/随机 seek 和重复定位一致；超出缓存边界不拼造历史 |
| M8.4 · 集成交付 | 完成受影响回归、资源和实际 Windows 流程 | 可运行包、数值与历史证据、人工仪器检查清单 |

默认第一交付先完成连续频谱及相关度/平衡/Lissajous，再补两种 Polar 表达。1/3 倍频程、整倍频程、临界频带、K-System 留作后续扩充，不作为本阶段最小完成条件；不能替代本阶段必须完成的基本视图。

**数值规则：**

- 频谱幅度明确采用何种标定和单位，不称为 LUFS，也不把对数坐标和频带聚合混为一谈。
- 历史平均、峰值保持和声场余辉由来源时间窗口确定，不随用户操作顺序累计。第一版用有界窗口；无限保持若引入，须另有明确原点/检查点规则。
- 默认历史频谱采用明确的因果窗口或显式标注窗口范围；不能在实时模式偷偷使用尚未到来的样本。
- 单声道不复制后伪装成实测立体声；静音/低能量时的相关度无效状态单独定义。
- 波形倍率、监听音量、颜色和视角都不改变原始测量。

**退出条件：**A17–A19 通过；每个发布的新仪器完整接通三种来源情形。数值参考、配置、时间范围和不支持项可追溯；不能只交付会动的图。

### 10.1 隐藏、冻结和历史的默认行为

- 隐藏面板停止其绘图与无用 UI 推送；录音、核心响度累计和已有 PCM 缓存生命周期继续。
- 新仪器再次打开时，从仍可得的缓存或文件补建所需窗口；超出缓存且没有文件的历史明确不可用。
- 历史查看冻结显示上下文，不自动发声；恢复实时使用当前健康输入。
- 仪器读数使用同一呈现位置查询，但 M/S、FFT、相关度各有自己的时间窗口和分辨率，不能声称它们是同一瞬间的样本值。
- 保留最后完整画面时必须有正确的呈现身份；慢结果不能在新来源/新游标标签下当成新数据。
- 报告或其他消费者需要的数据不因面板隐藏而停止收集；订阅与历史覆盖规则在 M7.0 明确。

### 10.2 预算与性能门槛

M7.0 为基准 PC 建立预算表：PCM/FFT/图形缓存上限、队列容量、CPU/GPU/工作集、刷新率、查询与取消延迟。数值在实现前确定，未填写预算不能关闭相应架构任务。

沿用 08 的定位目标：**缓存命中查询 p95 ≤100 ms；扣除已知输出缓冲后，显示与呈现位置偏差 p95 ≤50 ms**。标明测试素材、仪器配置和设备。首次分析、GPU 着色、FFT 时间窗口分别统计，不能用更粗的窗口掩盖延迟。

资源上限不能凭空写“CPU 小于 5%”。长时间运行应在预设预算内稳定，不随录音长度或布局切换次数持续增长。超预算时先减少绘图密度/推送频率和预取量；算法精度选项的改变必须显式、可追溯。

### 11.1 执行与证据

- 纯文案/低影响布局改动不机械新增单元测试；布局持久化、状态机、时序和新 DSP 必须有真实风险覆盖。

- 比较 Insight/上游时固定输入、声道、增益、分析窗口和保持条件，它们不能代替算法参考值。
- 新增测试脚本在实现任务中落地；本计划不虚构 `test:trace-spectrum` 等尚不存在命令。
- 目前已核对存在 `typecheck`、`build:trace`、`build:trace-engine`、`test:trace-contracts`、`test:trace-recording`、`test:trace-timeline` 等 package scripts，以及 `test/native` 和 `tools/m6`。具体执行前再次核对。

### 11.2 阶段关闭与故障处理

阶段状态统一为：待开始 → 设计中 → 实现中 → 工程验证中 → 待人工验收 → 已验收；必要时标“阻塞”，写清具体原因和可继续事项。

阶段关闭需要实现完整、受影响检查通过、使用说明/设计/接力同步，并交付可复现的包和人工检查清单。人工结果尚未收到时保持对应状态，不擅自改为已验收；不受其影响的下阶段设计可继续。

出现静默丢帧、录音被布局中断、跨来源/旧代次覆盖、同位置数值不可重复、错误删除原始文件或无界资源增长时，暂停相关阶段的发布/后续依赖集成，优先修复；不妨碍其他独立文档或研究。

硬件/素材暂缺记“未验证”及原因，沿用此前可用包。代码回退优先采用针对性提交回退或关闭新功能入口，保护已有录音、配置和未提交改动；不能整仓重置来掩盖问题。

### 11.3 面向使用者的整体验收任务

每个任务同时检查功能是否完成、入口是否容易找到、状态是否容易理解。记录完成步骤、误操作/求助点、响应延迟及用户反馈；工程人员代操作不等于用户验收。

| 任务 | 操作场景 | 验收重点 |
| --- | --- | --- |
| U1 · 配置自己的工作台 | 从默认布局改成响度检查，隐藏无关仪器、调整大小、保存并重启 | 无需了解内部模块；仪器能找回，原录音设置保留，紧凑面板不裁掉单位 |
| U2 · 找到刚才的异常 | 未录音监测时回看最近缓存，在波形/响度/2D 定位同一时刻，再回到实时 | 当前来源和覆盖范围清楚；图表、读数及游标一致，拖动不闪空或误发声 |
| U3 · 判断频率与声像 | 查看含窄带峰、扫频、左右反相和单边声音的已知素材 | 能解释频率、幅度、相关度与平衡；静音/未就绪不误导；2D/3D 相同点读数一致 |
| U4 · 录音时调整显示 | 录制中改布局、缩放、隐藏仪器、最小化再恢复，停止后回听 | 录音帧/故障状态可核对；没有因布局中断写盘或丢失监测意图 |
| U5 · 交付一段检查结果 | 导入素材，选区，设置目标，定位超限，导出音频及 CSV/HTML | 范围与口径可追溯，界面/报告一致，失败可重试，原文件保持不变 |
| U6 · 和参考素材比较 | 导入一份参考，设定比较范围/偏移，A/B 试听和比较，再清理缓存/库记录 | 来源不混淆，试听增益不污染测量，清理边界清楚，外部原文件保持不变 |

视觉复核固定检查：石墨灰底色与 Trace 绿色标识、统一标题/仪器控件、等宽数值及稳定单位位置、正常/选中/警告/错误层级、可见焦点和图标说明。常态保留简洁界面，解释按需出现；图表异常同时有标记或可读取状态，不只靠颜色。实时图表的这部分检查参考 UI/UX Pro Max 的 Real-Time Streaming / Anomaly Detection 指引，具体控件和缓存上限仍以 Trace 约定为准。

## 12. 暂不纳入本轮路线的范围

- 多声道/Atmos 对象、多个系统设备同时采集、ASIO/DAW 总线直接接入。
- Relay 类跨插件通信、对白识别/对白门控/可懂度算法。
- 独立仪器浮窗、多屏自由停靠、任意多个同类仪器。
- 同录同播、音频修复/降噪、完整编辑器、自动混音或标准响度处理。
- 云同步、账号、音乐平台服务及插件宿主。

这些内容需要独立的需求和算法/输入路径评估；不因模仿竞品外观自动进入当前实现。外部本地文件导入已明确纳入 M12，不再仅列为模糊远期愿望。
