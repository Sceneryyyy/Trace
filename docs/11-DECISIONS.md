## ADR-001 的备用路线

如果 Prism 构建/许可材料可接受，但其数据路径必须大范围牵动无关功能才能得到完整帧与稳定时钟，或者原生模块在目标环境上无法形成可维护的录音边界，记录原型证据与预计改动范围后切到既有备用方案：独立 Windows 应用，NAudio + WPF + libebur128，FFmpeg 仍用于压缩输出。

环境缺工具、网络无法下载、一个类型错误不是切栈理由。先解决可定位的问题。若已有 vstdev 模块提供明确更低成本路线，应记录具体模块、接口、测试和迁移成本，再更新本 ADR；不能同时保留三套产品实现。

主路线一旦通过 M0，本阶段按其推进；M1 以后换栈必须列出已实现能力的保留方式和测试迁移，不从“更现代/更适合 vibe coding”等泛泛描述开始重写。

## ADR-001 · M0 实测结论（2026-09-15）

锁定 Prism 可在目标 Windows 构建和加载，独立原生消费者成立，保留主路线。Realtek 空闲无包但帧号连续的实测说明 CaptureClock 必须结合 QPC、覆盖区间和 estimatedSilence/gap 语义，作为 M1/T10 首项实现；不采用直接扩展显示队列或只累计包帧数的录音路径。96 kHz 待真实配置验证。详细范围、命令和证据见 16。
