# 03 · 音频、计量与时间规范

preview.4：当前连续录音段的有界历史使用该段自己的 Meter。活动 freeze 仅包含已发布计量前缀；true-peak 前视尾部不进入可查看范围。计量算法和容差不变，见 31。

本文定义产品语义。标准相关数值以 EBU 测试资料和所选算法实现为依据；界面刷新率、缓存步长和性能目标是项目设计值，不是标准容差。

## 采集格式与帧

从 `GetMixFormat` 取得采样率、声道、容器位数、有效位数和浮点/整数表示。内部分析按声道转换为 float32，但保留采集格式元数据；float32 表示不等于硬件有效精度。采集、分析、波形都使用实际采样率。

一帧包含同一时间的全部声道。`frameCount` 不能乘声道后仍称帧数。原生位置用 uint64；跨 JSON 的帧数/纳秒用十进制字符串。设备重开生成新的 `captureEpochId`，绝不跨 epoch 比较设备帧号。

每块数据含 `epochId`、`sequence`、`firstFrame`、`frameCount`、`sampleRate`、`channelCount`、设备位置、QPC 时间和标志。`GetBuffer` 的 QPC 位置是 API 给出的 100 ns 单位时间，不是直接的 QPC tick。读取与释放在正确线程成对进行；WASAPI 指针释放后不得继续引用。

## 静音、缺口与空闲

| 输入情形 | 处理 | 计量/时间轴 |
| --- | --- | --- |
| 正常 PCM | 原样进入完整分析与录音分支 | 时间连续 |
| 有帧数且 `SILENT` | 按帧数构造零样本，不读无效指针 | 正常静音，M/S 可降至静音状态 |
| 暂时 `BUFFER_EMPTY` | 等待并检查设备/时钟，不立即推断丢帧或静音 | 不重复消费上一音频块 |
| 端点空闲、无应用播放 | 用原生时钟和恢复后的设备帧锚点验证连续时间策略 | LIVE 读数衰减到静音；录音需要保持真实静音时长 |
| `DATA_DISCONTINUITY` | 记录缺口及已知/未知帧长；能恢复时继续新连续区间 | 标注异常，不能显示“全程完整” |
| `TIMESTAMP_ERROR` | 数据可保留但位置质量降级，尝试重新锚定 | 不把推算时间冒充可信设备时间 |
| 设备失效/暂停恢复 | 完成可用分段并重开 epoch | 明确缺口；重新初始化实时测量 |

空闲期是 M0 的硬验证项。不能复制 Prism 按每次轮询耗时取整补零的代码就声称样本准确。若需要补零，统一在 CaptureClock 中记录覆盖区间、余数和原生时间锚点，给补齐区间标 `estimatedSilence`，恢复真实包后去重/对齐。误判缓冲抖动、重叠帧和累计时长漂移必须通过“播放→静音→播放”夹具发现。无法建立可信映射时保留异常标记，不能合成一条看似精确的无损时间线。

## REC 起止语义

前端提交开始/停止请求；引擎在采样块边界确认实际 `startFrame` 和 `endFrameExclusive`。未来可支持块内边界，但首版不声称按按钮的 UI 时间等于样本准确起点。音频有效区间一律左闭右开 `[start, end)`。

新 take 的计量从其首帧独立启动，不包含 REC 前的 live 上下文。live 累计器仍运行。停止只关闭写盘与 take 累计。文件头、日志和样本总数均使用引擎确认的边界。

## 数值与显示含义

| 项目 | 定义与单位 | 缓存/显示建议 |
| --- | --- | --- |
| Sample Peak | 各声道窗口内绝对样本最大值，转换为 dBFS | 非重叠 10 ms 块保存原始 max；显示保持状态另存 |
| RMS | 各声道滚动 300 ms 的平方均值开方；未 K 加权，dBFS | 可配置窗口，默认 300 ms；不得标 LUFS |
| True Peak | libebur128 真峰值估计，dBTP | 处理插值滤波上下文及引擎延迟；区分窗口/全段最大值 |
| M | 400 ms 窗口的 momentary loudness，LUFS | 每 100 ms 存历史；不是把 400 ms 峰值换标签 |
| S | 3 s 窗口的 short-term loudness，LUFS | 每 100 ms 存历史 |
| I 截至游标 | 文件起点至当前索引的 gated integrated loudness，LUFS | 录制/离线扫描时按前缀生成，不随回听重新累计 |
| I 整段 | 某一音频资产完整内容的 integrated loudness | 文件分析完成后固定 |
| LRA | loudness range，LU | LIVE 持续更新；FILE 默认整段统计；不足 60 秒标“暂估” |
| Max TP | 所选资产所有声道的全段最大 true peak，dBTP | 固定文件统计，和当前 TP 分开 |

首次不足 M/S 窗口时显示“测量中”，不伪装成稳定读数。I 尚未得到有效 gated block 时为未就绪。无有效声音时 LUFS 可为负无穷；JSON 使用 `null + status:"silence"`，界面显示 `−∞`，不能把它转换为 0 LUFS。缺口则使用 `status:"gap"`，不等于静音。

响度以原声道布局计算。单声道显示复制到两个视觉条时，不能复制音频后当成立体声计量。首版超过两声道明确拒绝；后续再引入有文档的声道映射/降混。

## 引擎设置与内存

统一封装 libebur128 的 M/S/I/LRA/Sample Peak/True Peak；记录精确版本、build、模式位、声道映射和窗口设置。先用官方测试集确定实现覆盖与误差，再谈与 Insight 2 对照。

长期 LIVE 的累计状态也必须有界。验证 libebur128 histogram 模式是否满足内存和数值要求；如果使用有限 `max_history`，不得继续把结果标为“从本轮开始的 I”。不得为节省内存悄悄改成只累计最近 30 秒。相关选择由 ADR-004 固定。

录制端和离线端采用相同数值配置、样本处理顺序与块边界规则。计量模块不盲目继承会改变浮点语义的优化开关。True Peak 的滤波延迟、头尾 flush 和历史时间归属需要独立脉冲/跨块测试；M0 的现有上游表头不作为唯一数值基准。

## 历史回放

FILE 的测量对象是用户选中的音频资产。位深转换、重采样或有损编码后，按成品重新分析。原始录音可以保留自己的历史，但必须有独立来源标签。

游标 `t` 的 M/S/I 历史查最近的、不晚于 `t` 的有效索引；100 ms 是默认查阅精度。不得线性插值 LUFS 冒充标准测量。电平缓存默认 10 ms。暂停时峰值保持和衰减冻结；播放时按文件呈现时间继续。同一时间重复定位，原始缓存数值应完全一致。

长文件加载可先构建粗波形，再后台构建详细分析。扫描到哪个位置就报告哪个位置；超过有效缓存时显示“分析中”，不从零重新累计 I 冒充历史。仅预读前三秒无法恢复文件起点以来的 I。

## 播放与选区

输出设备采样率可与文件不同。监听转换只影响输出适配；表头保持所选文件自身的分析口径，不受监听音量影响。播放游标使用输出设备的实际呈现位置，并通过重采样比率、解码延迟与缓冲映射回文件帧。UI 计时器只做两次可信快照之间的视觉插值。

拖动开始记住是否正在播放，暂停输出；移动时更新游标和历史查询；松开只在原来播放时继续。每个 seek 增加 `playbackGeneration`，旧解码结果必须丢弃。点击定位同样走该逻辑。

选区 `[a,b)` 作为独立节目，从空分析状态测其 I/LRA/TP，循环播放不重复累计。记录边界和首尾处理策略；不能对历史 LUFS 求算术平均来当选区 I。历史表头仍按文件坐标显示，选区统计另置。

标准与 API 来源索引见 [14-SOURCES](14-SOURCES.md)；可判定测试见 [08-ACCEPTANCE](08-ACCEPTANCE.md)。

## M2 原生映射记录（v2，现由 v3 替代）

native/src/recorder/Meter.h/.cpp 为 LIVE、take 和后续 FILE 的统一入口。配置标识 trace-meter-v2-ebur128-1.2.6-histogram，模式 M/S/I/LRA/TRUE_PEAK/HISTOGRAM，单声道或双声道的原始声道数不复制计量。

v2 增加显式 finish：不整 10 ms 的末尾帧仍进入计量，M/S/I/LRA 固定于真实 EOF；另给插值器 64 个零帧以取得最后的 TP，但不把补零算成音频时长或文件帧。push 在 finish 后拒绝，重复 finish 幂等。

REC 中源信号按独立 Meter 计量；WAV 整数舍入/手动重采样后的成品在 M3 建立独立缓存。当前不能以源 Meter 代替保存文件的测量。分块/极低电平/末尾/静音检查见 17/19；官方 EBU 素材测试待 M3，不将上游合成夹具当成官方素材通过。

上述为 M2 初始阶段行为。当前已实现原设备可恢复故障的同会话续录，跨 epoch 时间映射和缺口记录见 23；磁盘及程序故障仍安全结束。

## M3 的 v3 修正记录（现由 v4 替代）

当前 ID：trace-meter-v3-ebur128-1.2.6-lra10hz-eof。C++ 定义在 MeasurementConfig.h，TypeScript 定义在 analysisTypes.ts；worker 验证二者一致，缓存还绑定原生二进制 SHA256。

标准复核发现 v2 使用的上游内部 LRA 步长为 1 秒。现已在 Trace 使用的 histogram 模式中改为 100 ms；源码补丁与前后 SHA256 见 native/vendor/libebur128/SOURCE.json。原始上游信息和许可保留。

finish 使用 1.5 秒零分析上下文完成 LRA/TP；真实帧数和 EOF 的 M/S/I/RMS/Peak 不变，不写入任何额外 PCM。52 个原生 case（含 18 个生成参考）通过。原始 EBU WAV 尚未取得，不能宣称该测试集通过；详细失败复现及范围见 20。

## v4：完整时间窗口的发布

当前配置 trace-meter-v4-ebur128-1.2.6-lra10hz-tpaligned。TP 使用同一库的原生插值输出，补偿 24 个输出样本的群延迟后归入源 10 ms 窗口。未来 6/12 个源帧可用后才发布对应窗口，所有字段带实际索引；停止时排空，真实帧数不变。首尾使用已声明的零延拓归属。详见 21。

## 录音快照一致性

Recorder 的 Meter/波形/响度、已写帧数、估计帧数和 QPC 两端在同一次锁定内发布，避免显示点超过同一快照的区域边界。写盘在锁外，capture producer 不取得此锁；故障不得用裁剪波形掩盖。并发回归及异常处理见 23。

## M4 文件呈现与选区实现

见 25。文件输出使用 IAudioClock position/frequency；暂停冻结输出，seek 刷新 generation，循环按累计流帧映射文件位置。M/S/I 使用文件历史，整段 LRA/Max TP 独立；选区 [a,b) 从空 Meter 分块分析。回听默认请求 Media/RAW，不改变文件测量，RAW 无法使用时回退普通共享流。原始 EBU 素材仍未验收。

## 60 秒内存历史回听（2026-09-16）

ReplayBuffer 在 analysis owner 线程接收原始 float32 样本及统一 Meter 每 10 ms 完整对齐的发布记录。PCM 容量实际采样率 × 声道 × 60 秒，计量记录固定 6002 条。REC writer 仍使用独立队列。

设备/测量 epoch、用户 reset、缺口会清空回听缓存，不拼接缺失数据。进入 HISTORY 先停止并排空采集/分析，再冻结最多 60 秒的不可变 PCM 与历史；PCM 留在 C++，前端只接收元数据和快照。不创建 WAV、压缩或分析缓存文件。

回听复用 WASAPI 呈现时钟、seek generation 和循环映射。主表头读取采集时已发布的历史，I 是原监测起点至当时的累计；选区另用同一 Meter 在后台分析，最多一个任务运行并合并后续请求。回到 LIVE 重开累计。计量算法版本不变，临时 ReplayInfo version 1 独立于磁盘缓存。

## preview.3 录音与监测意愿

monitoringRequested 记录用户是否需要常驻 LIVE，active 仍表示实际采集。监测关闭时，REC 按需启动同一原生采集引擎并持有临时使用权；正常停止、启动失败或快照故障完成收尾后释放。已有常驻监测时，REC 不重启采集或重置其统计。选择目录被取消时不启动采集。FILE/HISTORY 退出也恢复监测意愿。恢复设备期间仍使用既有录音代次保护。

显示窗口扩展为 5–60 秒有限实数；原生按向上取整的秒数读取已有显示历史，前端精确裁切到选择窗口。DSP 时间窗、历史步长、样本率、录音 PCM 和数值算法不变。
