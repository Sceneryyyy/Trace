# 32 · preview.8 历史游标连续呈现

2026-09-16。用户提供 13 秒、60 fps 录屏，反映拖动历史游标时电平柱和 M/S/I 数字闪烁。

## 原因与修复

- 旧界面每次 seek 提升 generation 后，将尚未匹配新代次的历史快照置空；下一份快照到达才恢复，连续拖动反复显示“—”和空柱。
- 拖动还会重复切换全局 busy；全局 stateRevision 用于历史数据过滤时，音量/录音状态等无关变化也可能丢弃有效数据。
- 新增 HistoryPresentation：保留上一份完整呈现，按来源、游标代次、可视范围和事件序号接纳新快照。数字、表头、显示位置与青色游标共同采用已完成的快照。
- 连续定位按动画帧合并；每次定位等待对应呈现后再提交最新指针位置，避免慢查询被不断失效。等待发生在连续交互队列内，主命令队列仍可停止、录音或切换来源。
- 主进程在 seek / inspect 完成后立即尝试只读采样，周期轮询负责补发；继续独立观察采集与录音。录音元数据采用最近一次已观察的完整录音快照。
- 连续定位不再反复切换全局 busy。失效来源、数据故障、静音、未就绪仍按真实状态呈现；不平滑、不插值、不重新计算 LUFS/TP。

## 验证

- 修改前基线：两段快速拖动分别采集 102 / 101 个渲染帧，其中 47 / 60 帧数字为空。原始记录在 artifacts/scrub/baseline-latest.json 指向的目录。
- tools/scrub/run-ui.cjs：文件正向、反向、增加 45 ms 异步读取延迟，以及真实 WASAPI 内存缓存拖动。逐渲染帧统计空白、空表头、busy 闪烁和实际位置/数值更新；抽查拖动中的位置并独立查询缓存，精确核对 I/M，最终电平和累计响度逐字段核对。
- test/history-presentation.test.mjs：无关 revision、迟到结果、窗口变化、来源切换、故障、静音/缺口和取消等待。
- 既有工作台、走带/EOF、直接录音和采样边界回归继续执行；原生计量和音频文件缓存算法未修改。
