## 用户可用流程

- 顶部“目标”管理自定义、EBU QC/直播参考预设，以及 I/TP/LRA/M/S 比较范围。旧响度目标线迁移到独立目标设置，布局和显示倍率不改变目标。
- 响度历史显示 I 目标范围带和可见曲线超限 × 标记。标记使用实际显示点；完整观察窗口事件由原缓存报告给出。状态条明确整段/本轮/当前段/截至游标口径，M/S 标为当前值。
- 走带栏“报告”支持整段或选区独立分析，显示任务进度、取消/重试、目标变更提示。事件分页每页 50 条，定位后返回同一时间轴、不自动发声；来源与测量 PCM 身份不匹配时拒绝定位。
- 未启用目标时仍显示测量结果；短于 60 秒的 LRA 不用于目标判断。静音、未就绪、缺口和错误分别保留。
- HTML 与三份 CSV 保存范围/单位/状态/完整性/分析身份。计量 PCM hash 与编码媒体身份区分；压缩成品不借用原 WAV 的测量或报告。

## 服务、资源和文件归属

ReportService 串行运行独立 report-worker，一次最多两项待生成任务，保留最多八份临时预览。完整报告不进入周期性 TraceState；report.get 按需返回最多 1000 条事件预览，CSV 保留全量。生成/复制均分块；预算与算法口径见 [50](50-M11-TARGET-REPORT-DESIGN.md)。

报告持有独立的 AnalysisService 引用计数。关闭文件视图不释放报告的引用；取消后也须等 worker 退出才允许自动源清理。删除录音、清缓存或切录音目录前取消并等待报告任务释放。REC 开始后报告让出资源并保留固定目标/范围，录音结束后重新扫描；复制导出取消后可重新导出。

临时目录使用 UUID 与 owner.json 身份标记。重启只清理自身标记下的四个已知报告文件，未知文件/目录不递归删除。导出使用用户选定目录下的新子目录，排他创建、逐文件校验，HTML 最后发布；失败只移除本次创建的文件，已有报告和原音频保留。

## 白名单接口

| 命令 | payload | 行为 |
| --- | --- | --- |
| targets.configure | settings | 严格验证、保存目标设置；不改变音频或分析缓存 |
| report.prepare | playbackId、scope | 固定当前整段/选区来源，建立后台任务 |
| report.get | reportId | 按需读取有限结果，不进入命令回复缓存 |
| report.cancel | reportId | 可直接中断生成或复制，不等待 mutation 队列 |
| report.retry | reportId | 从保留来源重新生成，采用当前目标，得到新报告 ID |
| report.jump | reportId、index | index 为 0–999，核对当前文件身份后定位 |
| report.open / export | reportId | 打开私有 HTML 或通过主进程目录选择导出 |

UI 不传任意来源/输出路径。测试目录选择和缓存清理确认只在 --trace-test、显式环境变量和测试根目录边界同时满足时生效；原生系统确认框的人工交互仍需单独复验。

## preview.21 回归失败与处理

完整门禁 artifacts/m11/final-1789594555700/report.json 在已通过 28 阶段后，package-smoke 重开已转码 MP3 时失败：FILE_WORKER_EXIT 3221225477（0xC0000005）。实际失败文件保存于 artifacts/m6/package-1789594731242；已有成品和源处理清单保留。当时 reportUsage 显示没有报告任务，失败发生在纯只读 hash worker，未加载计量原生模块。

使用失败时同一批编码/解码文件，对 preview.20/21 交替进行 40 次独立 hash worker 调用，40/40 通过；两版本各两次完整录音/转码/清理/重开流程均 8 项通过。证据 artifacts/m11/worker-repro-1789594807873/report.json、artifacts/m11/smoke-comparison-1789594847716/report.json。未发现可用 Windows 崩溃报告，底层退出原因仍未复现，不能将复测通过称为根因已修复。

preview.22 对该明确退出码的只读 hash 任务增加一次新进程重试，并记录 TRACE_HASH_WORKER_RETRY。成功必须返回重新计算的真实 hash，后续原有 hash 比较不变；第二次失败、取消、文件变化及普通 I/O 错误继续报告失败。该策略不覆盖写入、解码、恢复或分析任务。两项故障注入测试验证次数、诊断和失败传播；保留原始失败，不放宽门禁。
