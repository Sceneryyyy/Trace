## 结论

Trace 已有完整的录音与分析工作流：三格式、录音分段与恢复、60 秒内存缓存显式保存、确定性历史、频谱/声场、共轴 2D/3D、范围报告和 A/B。最有价值的下一步是把这些能力做得更可靠、更快、更容易判读。

建议顺序：先建立资源/长文件基线并补故障收尾；再优化频谱与声谱计算和缓存；随后增强频谱判读、等响度 A/B 与标记复核。Windows 设备、慢盘、两小时录音和 GPU/DPI 的缺口仍优先，见 [76](76-RELEASE-CHECKLIST.md)。没有依据为了本次调研更换 Electron/C++/WASAPI/libebur128/自建 FFmpeg 技术路线。

### 两项优先优化的依据

**FFT 复用是源码机会，不是已测定的瓶颈结论。** 当前一个最多 64 列的声谱 tile 会多次构造 FFT/窗/临时数组，且走完整 `analyzeInstruments` 的声场逻辑。把资源准备移到配置生命周期、提取共享频谱内核，可能减少重复成本。不能直接改成随播放连续累计的状态机，否则随机 seek 的平均/保持可能失去确定性。参考谱与声谱的窗口结束帧/hop 可能不同，也不能仅凭“同来源”盲目共享结果。

**声谱磁盘增长有可计算的上限需求。** 当前 Float32 全频点存储，`hop=min(N/4,rate/50)`。48 kHz、FFT 2048 时约 93.75 列/秒，1025 bins，全部覆盖一小时的纯数值约 1.38 GB；FFT 16384 时 50 列/秒、8193 bins，约 5.90 GB/小时。这里是十进制理论值，未含 tile 头/文件系统开销，并非测得的当前用户缓存量；实际只写已请求覆盖的瓦片。两小时全范围浏览及多个 FFT/声道配置会放大成本。多级概览减少绘制和查询工作，仍须配套磁盘预算，不能只加一套缓存。

### 专业仪器增强的边界

- 建议第一批做频谱平滑、像素聚合与分辨率提示。当前 Hann 幅度缩放和线性功率平均已有契约，见 [41](41-M8-METERING.md)；窗函数/PSD/A-C 加权若进入分析定义，需另加身份、归一化及数值测试。FFT bin 相加不自动等价于符合 IEC 标准的倍频程滤波器组。
- 48 kHz / FFT 2048 的 bin 间隔约 23.44 Hz、窗长约 42.67 ms；FFT 16384 约 2.93 Hz、341.33 ms。显示这些权衡比单独提供 FFT 数字更容易理解。零填充可让曲线更密，但不增加真实频率分辨率。
- 逐频带相关度、PLR/PSR、响度分布可在上述工作后引入。区分 crest factor、PLR 与 PSR；给出公式、范围与无效状态，避免多个相近指标同时挤入默认界面。
- 不把数字 dBFS/dBTP 直接称为声压 dB SPL。没有麦克风/设备校准，A/C 加权显示也不能成为声压测量仪。

## 当前不建议投入的方向

1. 扩成完整 DAW、VST 宿主、音频编辑器、多源混音器，或为了插件仪器改成 JUCE 主工程；偏离现有录音/复核目标且迁移成本高。
2. 先增加更多 3D 效果、主题、独立浮窗。现有视觉已较完整，频谱判读和长文件速度的收益更直接；GPU 实机门禁尚未关闭。
3. 用新计量库替换 libebur128/Meter v5，或把合成信号测试更多视为算法更可靠。Trace 已有原始 EBU 材料证据，应把外部实现用于独立反例和对照。
4. 自动响度归一化/限幅、AI 降噪/音源分离。会改变音频与测量语义，需要独立需求和成品验证；当前先做回听增益与 QC。
