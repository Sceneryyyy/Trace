# 桌面音频录音机：项目调研与功能布局方案

调研日期：2026-09-14。方案版本：0.3，补充可选保存参数，并将跟随系统 96 kHz 的要求限定到 WAV，供讨论和后续实现使用。

建议优先验证 Prism 的可复用性，保留其 Windows 系统声音采集和模块化计量界面，新增持续录音、文件播放与按时间索引的计量历史。响度计算优先采用 libebur128，避免为 M/S/I、LRA 和 True Peak 分别维护不同算法。若 Prism 的实时分析结构不适合持续录音和文件回放，则采用 NAudio + WPF + libebur128 的 Windows 路线。

这是基于官方资料、仓库说明和关键源码的工程判断。本轮完成调研和交互方案；没有在 Windows 实机编译或验收这些候选项目，也没有完成可执行录音机。界面示意使用演示数据，不采集或播放真实音频。

打开应用并选定有效来源后，默认进入“实时监测”。软件持续读取系统声音，计算电平、响度，并更新滚动波形和响度历史；未按录音时不写入音频文件。REC 只控制录音文件的开始和结束，停止录音不关闭实时监测。用户选择“录音回放”后，主表头和波形才切到所选文件，点击“返回实时”恢复系统声音显示。

| 工作状态 | 主表头的数据来源 | 主波形 | 音频文件写入 |
| --- | --- | --- | --- |
| 实时监测，未录音 | 当前系统声音 | 最近一段时间的 L/R 滚动波形 | 关闭 |
| 实时监测，正在录音 | 当前录音的源信号；录音计量独立累计 | 从录音起点不断延长的波形，可跟随最新位置 | 开启 |
| 录音回放 | 所选录音的音频和计量历史 | 可拖动、缩放、选区的完整录音波形 | 关闭 |

实时模式的 I/LRA 从本轮监测开始或手动重置后累计，不能把显示最近 30 秒误解为 I 只统计 30 秒。开始录音时，为新 take 建立独立计量状态，其累计值不包含按下 REC 前的监测音频；采集本身不中断。停止录音后默认回到实时表头，新 take 保持可选，可一键进入回放。实时与录音统计使用明确标签；实时统计重置不改变已保存录音及其历史，首版在录音期间禁用实时重置按钮。

首版回放时暂停系统声音的实时计量，主表头专门显示录音回放；返回实时后开启一轮新的实时测量，避免将暂停间隔或自身回放混入上一轮统计。它仍符合“未录音也能计量”：实时监测和录音回放都无需文件录制开启。后续若要同时看实时输入与文件回放，应使用明确分开的两组表头。

未录音时仅保留算法所需的短时音频窗口、有限长度的波形概览和响度历史。滚动波形本身不保证能回听过去的声音；“没有按 REC 也能回听/保存刚才 30 秒”需要另外保留原始 PCM 的回溯缓冲，该能力仍按后续功能处理。

Prism 本轮检查的主分支树标识为 `df0755b8caaaab85157ac51aefffca0526974fc1`。后续应锁定选定提交并复核，而非让开发环境持续跟随主分支。保留项目及依赖许可声明；本方案不把 GPL 组件描述为不能用于商业内部工作，也不把内部用途视为免除所有许可条件。

对照 Insight 2，建议保留其深灰底色、荧光绿有效信号、紧凑数字、明确单位和可调整模块大小的视觉逻辑，把波形与回放升为主体。

| Insight 2 的模块/能力 | 本产品的设计 |
| --- | --- |
| Levels：各声道 True Peak 与 RMS；可选峰值保持、RMS 积分时间 | 第一版 L/R 电平条、Sample Peak 数值、True Peak、RMS、最大值；清楚区分 sample clipping 与 TP 超标 |
| Loudness：M、S、I、LRA 等，面板大小改变显示密度 | 右侧固定可见 M、S、“I 截至游标”；独立显示整段 I、整段 LRA 和整段 Max TP |
| History：响度随时间变化，可查看某时刻读数 | 放在波形正下方，共享缩放、横向位置和播放游标；点击两个图的任意一个都能定位 |
| Layouts：保存面板布局和相关设置 | 标准录音布局先实现；紧凑计量布局与保存预设后续加入 |
| Sound Field、Spectrum、Spectrogram | 第二阶段的可选面板；不能挤占首版波形主视图 |

Insight 2 的 History 是响度历史，不是录音文件波形编辑器。依据官方说明，本产品需要额外实现音频保存与回放，以及音频和计量历史之间的时间关系。模块事实来源：[Levels](https://s3.amazonaws.com/izotopedownloads/docs/insight200/en/levels/index.html)、[Loudness](https://s3.amazonaws.com/izotopedownloads/docs/insight200/en/loudness/index.html)、[History](https://s3.amazonaws.com/izotopedownloads/docs/insight200/en/history/index.html)、[Layouts](https://s3.amazonaws.com/izotopedownloads/docs/insight200/en/layouts/index.html)、[官方界面介绍](https://www.izotope.com/community/blog/why-upgrade-to-insight-2?page=13)。这里只借鉴视觉层级和操作逻辑，使用自己的名称与界面资源。

| 更多分析面板 | 频谱、声像、相关度和频谱图 | 后续 |
| 多声道与同录同播 | 5.1/7.1、后台持续录音时回听前段 | 待用户确认后重新安排范围 |

32-bit float 是保存格式，不会恢复上游已经削波的信息，也不等同于声卡具备相同的有效位深。默认只测量，不自动归一化、施加动态压缩或限制源信号；监听音量不改变录音原始计量。向 24-bit/16-bit 整数格式导出时，应处理削波检测、位深转换和可选抖动。MP3/AAC 属于有损编码，其文件没有与 PCM 相同含义的“16-bit/24-bit 保存精度”选项；解码器输出浮点样本不表示压缩文件本身具备 32-bit 精度。

保存参数按格式联动，首版建议如下。下表为拟实现的选项范围，不表示所有组合已经在 Windows 验收。

| 保存格式 | 拟提供的常用采样率 | 精度/质量选项 | 来源为 96 kHz 时 |
| --- | --- | --- | --- |
| WAV，.wav | 跟随来源，或 44.1/48/88.2/96 kHz；首版验收上限为 96 kHz | 16-bit PCM、24-bit PCM、32-bit float | 可原采样率保存；建议默认“跟随来源 + 24-bit”，需要保留采集浮点表示时选择 32-bit float |
| MP3，.mp3 | 44.1/48 kHz | 例如 128/192/256/320 kbps 的 CBR 预设及 VBR 质量档 | 按所选参数转换为 44.1/48 kHz；在设置摘要中明确显示 |
| AAC-LC，默认 .m4a，可选 .aac（ADTS） | 44.1/48 kHz；不安排 96 kHz | 例如 128/192/256/320 kbps 的目标码率，按实际编码器能力提供；VBR 在映射验证后提供 | 按所选参数转换为 44.1/48 kHz；在设置摘要中明确显示 |

实现“跟随系统”时，读取所选播放端点的 WASAPI `GetMixFormat`，按其实际采样率采集，并把该数值传给计量、波形和写盘模块。默认不主动修改 Windows 的设备设置。若 Windows 音频引擎实际工作在 96 kHz，WAV 选择跟随来源即可维持 96 kHz，不必经过一次固定 48 kHz 的中间处理。若媒体文件本身是 96 kHz，但 Windows 混音格式是 48 kHz，loopback 得到的是系统混音后的 48 kHz；后续升采样到 96 kHz 不会恢复已丢失的信息。实际浮点采集格式也不等于声卡标称位深。依据：[Microsoft GetMixFormat](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat)。

格式限制依据：[FFmpeg 的 libmp3lame 采样率列表](https://www.ffmpeg.org/doxygen/8.0/libmp3lame_8c_source.html) 中最高为 48 kHz；[Microsoft Media Foundation AAC 编码器](https://learn.microsoft.com/en-us/windows/win32/medfound/aac-encoder) 的官方输入要求为 16-bit PCM、44.1/48 kHz。[FFmpeg 编码选项](https://ffmpeg.org/ffmpeg-codecs.html) 区分码率和 VBR 质量设置。根据用户最新补充，本方案只要求 WAV 支持 96 kHz；其他编码器具备的更高采样率能力不进入首版范围。

保存设置使用独立弹层，依次显示格式、采样率、位深/码率、声道、目录和命名规则，可保存为预设。选 WAV 才显示位深与“跟随来源”；选 MP3/AAC 则显示码率/质量与 44.1/48 kHz。底部始终显示结果摘要，例如“采集：96 kHz / 2 声道 / float → 保存：WAV / 96 kHz / 24-bit”，或“采集：96 kHz → 保存：MP3 / 48 kHz / 320 kbps”。来源采样率超出首版已验证范围时明确提示，要求先选择有效输出配置再开始该录音；不静默降采样。实时监测仍可正常运行。录制期间修改输出参数默认用于下一条录音，不在同一文件中途改变编码规格。

跟随来源不承诺系统重设设备时无缝切换。录制中设备采样率发生变化，先尽可能完成旧分段，重新读取格式并开启新分段；在会话时间轴标明格式变化和采集缺口。新的输出参数若不再兼容，则保留已有录音并停止该次文件录制，恢复可用的实时监测，提示选择有效配置。一个 WAV 分段保持一个采样率；各分段用自己的采样帧计数映射到会话时间，不能把不同采样率的数据直接追加到同一 WAV 数据区。

录音完整性优先于成品编码速度。无需转换的 WAV 可直接在写盘线程持续保存；MP3/AAC 或需要转换的 WAV，首版建议先保存源采样率的临时 PCM，再后台生成用户所选文件，界面显示“正在生成成品”。临时 PCM 会占用额外磁盘空间，应在保存设置中显示预计占用。成品成功写完并检查可解码、时长和参数后才清理临时文件，失败时保留以便重试；“另外保留原始 WAV”可单独勾选，默认关闭。未按 REC 的实时监测不产生此类音频临时文件。编码过程不阻塞采集或实时表头。

压缩编码、重采样和位深转换可能改变波形、峰值与响度，因此源信号计量和成品计量分别保存。录制中的表头始终标注“采集源”；回放 WAV/MP3/AAC 成品时，按该文件解码后的音频建立波形、M/S/I/LRA/TP 及历史索引。不能把源 PCM 的读数直接标为 MP3/AAC 成品读数。编码延迟、首尾填充、重采样后的帧数和分段时间映射均须纳入定位处理；缓存绑定文件标识和分析配置。如果成品尚在生成，可明确显示并试听“原始录音”，生成完成后由用户选择成品，避免播放中自动换源。上述分离是为满足“所听文件与回放表头一致”的工程设计。

“重放表头”的含义必须在实现前固定。推荐默认“历史回放”：播放到 00:01:00 时，表头显示所选文件 00:01:00 对应的数值，而不是每次跳转都重开一轮累计。无转换的源录音可复用录制时的历史；经过编码、重采样或位深转换的成品使用独立分析结果。

| 显示项 | 历史回放中的含义 | 拖动后的行为 |
| --- | --- | --- |
| Sample Peak / True Peak / RMS | 所选文件在该时间附近的电平；各自保留独立单位与窗口 | 恢复对应时间的缓存/计算结果 |
| M | 对应时刻的 400 ms 窗口响度 | 包含该时刻之前的音频上下文；不足窗口时标示尚未就绪 |
| S | 对应时刻的 3 s 窗口响度 | 跳到中间不从空窗口重新积累 |
| I 截至游标 | 从录音起点到当前时间的 gated integrated loudness | 跳回以前的时间就恢复以前的累计结果；不会把试听次数算进去 |
| 整段 I | 全部录音文件的 integrated loudness | 固定显示；后台尚未分析完则显示进度 |
| 整段 LRA | 全部录音的响度范围 | 固定显示；短素材应标示统计不稳定，不制造精确感 |
| 选区 I / LRA | 所选音频片段作为一个独立节目的测量 | 选区改变才重算；不得把历史 LUFS 值取算术平均来替代 |

EBU Mode 的 M/S/I 时间定义和测试方法见 [EBU Loudness](https://tech.ebu.ch/loudness) 与 [Tech 3341](https://tech.ebu.ch/publications/tech3341)。EBU 对短时间 LRA 的不稳定性另有说明，见 [2016 年更新说明](https://tech.ebu.ch/news/2016/08/ebu-loudness-changes)。首版可将不足 60 秒的 LRA 标注为“暂估/不稳定”，而非作为已稳定的最终统计。

状态转换应保证录音源、回放文件和表头来源不会混淆。

| 当前状态 | 用户动作 | 音频与表头结果 |
| --- | --- | --- |
| 已选定有效来源 | 开启实时监测 | 未录音也持续显示系统声音电平、响度与滚动波形，不写音频文件 |
| 实时监测 | 点击录音 | 采集不中断；建立新 take；录音计量从该 take 起点开始 |
| 录制中 | 点击停止录音 | 完成源录音/分段索引并保留历史；继续实时监测；需要转换则后台生成成品并显示进度，原始录音可先回放 |
| 实时监测，未录音 | 选择录音回放 | 主视图切到录音文件；暂停实时计量，尚不播放音频 |
| 录音回放，已暂停 | 点击波形 | 移动游标并显示文件历史读数，保持静音 |
| 录音回放，已暂停 | 点击播放 | 从游标开始输出录音，同时推进电平、响度和历史游标 |
| 播放中 | 拖动游标 | 暂停输出并更新定位预览；松开后从新位置继续播放 |
| 暂停中 | 拖动游标 | 更新历史读数并保持暂停 |
| 选区循环中 | 再次经过同一区域 | 原始 I 截至游标按原时间恢复；选区统计不因重复播放而累加 |
| 录音回放 | 点击返回实时 | 停止文件播放；显示系统声音，开始新一轮实时计量，不写音频文件 |
| 实时监测，未录音 | 点击重置计量 | 重置本轮实时统计及响度历史，不改写已录文件及其计量历史 |
| 回放准备/暂停 | 点击录音 | 回到系统声音采集，建立新 take，不覆盖上一个录音 |

拖动时连续发出短音片段的 scrub audition 可作为独立选项后续加入；它与拖动定位后正常播放不同。本示意按后者设计。

实现上将采集分析的生命周期与文件写入分开。实时模式的采集线程持续向有界队列提交 PCM；计量和波形分析持续工作；只有录音开启时，文件写入分支才工作。使用采样帧位置关联音频、数值和波形；界面只读取已准备好的数据，不能让窗口帧率决定实际参与响度计算的音频数量。实时滚动显示缓存与录音文件的完整索引分开管理，未录音时不建立无限增长的历史文件。

| 数据层 | 建议保存内容 | 用途 |
| --- | --- | --- |
| 音频 | 用户选择的成品文件及格式参数；生成成品前保留临时源 PCM；原始文件可选额外保留；记录分段边界 | 回放及重新分析的依据；不同版本音频绑定各自的分析结果 |
| 波形缓存 | 多分辨率 min/max，按声道存储 | 数小时文件也能快速缩放 |
| 快速电平历史 | 建议 10 ms 固定步长的峰值/TP/RMS；必要的保持与衰减状态 | 平稳且可重复的表头回放 |
| 响度历史 | 建议 100 ms 固定步长的 M、S、I 截至该时刻 | 拖动立即查阅；真实计算与 UI 更新频率独立 |
| 文件汇总 | I、LRA、Max TP、采样帧数、测量设置与引擎版本 | 最终统计与一致性检查 |
| 会话元数据 | 文件标识、源采集格式、成品格式、编码器版本、转换/延迟映射、设备、标记、选区、异常区间、配置版本 | 重新打开、定位映射与缓存失效判断 |

100 ms 是本方案拟定的响度历史索引精度，不是对标准允许误差的声明。播放时以音频实际呈现位置驱动游标，并考虑输出缓冲；不能只用 UI 定时器累加时间。向前送入播放缓冲的数据尚未全部被听到，不能提前显示对应表头。

历史回放直接读取与时间关联的测量值，避免每次跳转从头扫描。若导入文件缺少缓存，先后台建立；若要在新时间点重新启动分析，需要恢复滤波器及窗口上下文。只补读前三秒足以覆盖某些短时窗口，却不能恢复从文件开头积累的 I，也不能保证全部滤波器状态等价。选区分析使用独立状态和确定的边界规则。

源文件、采样率、声道配置或测量算法设置改变时，旧缓存应失效。改变图表颜色、缩放或监听音量不应触发重新计量。离线文件的峰值保持应按文件时间推进，暂停时冻结，而不是继续用电脑的墙上时钟衰减。

Windows 采集范围以官方 API 定义为准：设备 loopback 对应一个选定的播放端点，不自动覆盖电脑所有输出设备；普通 loopback 仅支持 shared mode。以后如果需要录 Nuendo 等 DAW 的 ASIO 输出，应单独验证其路由，不能承诺普通系统 loopback 必然可见。[Microsoft：Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

“只录一个程序”和“排除录音机自身”可研究 Microsoft 的 process loopback。官方样例要求 Windows build 20348 或更新版本，不能笼统视为所有 Windows 10 都支持。边录边回听需要解决自身播放声音被重新采入的问题，因此未在用户确认前作为首版必需能力。[Microsoft：Application loopback audio capture](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)

建议按以下顺序验证和实现，先用证据确定底座，再做完整界面。

| 步骤 | 产出与通过条件 |
| --- | --- |
| 0. 未录音实时监测 | REC 关闭时播放系统声音，确认所有实时表头和 L/R 波形更新且无音频文件写入；反复开始/停止录音不停止采集；实时累计和 take 累计相互独立 |
| 1. Windows 采集验证 | 在 44.1/48/96 kHz 实际设备配置下录制已知测试音；核对真实采集率、首部、静音段、采样帧数、声道顺序和停止后的文件完整性；检查 Prism 是否保留原始格式供持续写盘；验证中途修改设备格式的分段与缺口 |
| 2. 最小录制回放链路 | 可录至少 30 分钟并重新打开；UI 拖动或最小化不能中断写入；验证断开设备和写盘错误后的数据保留 |
| 3. 统一计量与时间索引 | 使用 EBU 测试素材验证 M/S/I、LRA、TP；同一文件在实时输入和离线扫描中符合测试素材的容差要求 |
| 4. 拖动及重复回放 | 测试静音、瞬态、前 400 ms/3 s、循环和任意跳转；定位到同一时间应恢复相同的历史读数 |
| 5. 格式与导出 | 验证 WAV 16/24-bit 和 float32 的选项及成品参数；重点覆盖 WAV 跟随系统 96 kHz。MP3、AAC/M4A 验证常规 44.1/48 kHz、重采样时长、编码首尾填充和编码失败保留原始录音；成品回放的波形和历史必须来自该成品 |
| 6. 界面整合 | 实现布局、采集/保存参数摘要、预设、独立监听音量、选区统计与导出；在目标 DPI 和多显示器条件下检查读数可读性 |

验证数据使用 [EBU Loudness Test Set](https://tech.ebu.ch/publications/ebu_loudness_test_set)；按其使用条款取得和使用。与 Insight 2 比对时固定标准版本、gate、声道映射、窗口和输入信号；相近的截图不能代替数值测试。用户电脑的录音完整性、CPU、内存、长录音能力和实际计量误差仍需后续实测，本轮没有虚构性能成绩。

现有交互示意仍展示录音回放状态，覆盖双声道波形、共用游标的响度历史、拖动定位、播放/暂停示意、缩放/全长和随时间更新的数值。方案已纳入未录音时的实时计量、实时波形、状态切换、自定义保存参数和 WAV 跟随 96 kHz 的规则，示意尚未新增实时模式或保存设置弹层。真实采集、录音、播放、磁盘保存、选区分析和声卡适配属于后续实现范围。
